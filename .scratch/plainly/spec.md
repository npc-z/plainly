# Plainly v0 规格

Status: ready-for-agent
Labels: ready-for-agent

> 由 `.scratch/plainly/` 的 wayfinder 地图与 18 张票据坍缩而成（票据 11 明确出界，规格由 `/to-spec` 产出）。
> 领域词一律按仓库根 `GLOSSARY.md`；`docs/adr/0001` 是 Explanation schema 的硬约束。
> 本规格的实现决策**逐条可追溯到票据**，见文末溯源表。

## Problem Statement

读懂一段难的英语，现在的工具没有一个帮得上忙：

- **查词工具解释单个词，不解释整句。** 一段文学、法律或正式英语里真正挡路的是习语、搭配、语域和句子的形状——`bottled it`、`to put it mildly`、`indemnify X against Y`、`Not until … did …`。词典给出的是生僻词条，逐词查完仍然读不懂那句话。
- **整段机翻把难度和结构一起抹掉。** 机翻给的是母语译文，读起来顺，但学习者既没有"用更简单的英语重说一遍"这层脚手架，也没有办法确认自己理解对了；原文里的反讽和轻描淡写往往被拉平。
- **云端 chatbot 要手工搬运。** 复制、切窗口、粘贴、写提示词、等回答、再复制回来。结果不留痕，问过的句子第二次还要重问，而且**把剪贴板里的密码误发出去**这类风险用户根本不会预料到。
- **长文本与脚本没有出路。** 想要批处理一整个文件，或者把解释接进管道、接进自己的编辑器，没有任何可用的命令行入口。
- **解释的可信度不可见。** 用本地模型离线跑时，它会自信地把习语讲错；界面若不显示解释出自哪个模型、也不给核对原文的位置，学习者会把错的记成对的。

具体处境是：一个中文母语者读英文原文（论文、小说、合同、邮件），想让难点被**用英语**讲清楚，需要时再看一眼母语翻译确认——而且要快要轻，不要打断阅读。

## Solution

用户按一次快捷键，Plainly 取出剪切板里的 **Passage**，产出一个 **Explanation**——分级英语改写（Comprehensible English）+ 逐条 **Gloss**（习语、搭配、语域）+ 可选的 **Grammar** 说明 + 母语 **Translation**——并在不抢键盘焦点的浮层面板里立刻呈现。同一个键再按一次就换上新一段；重复的段落直接命中本地历史库，不再花钱。

每个 Explanation 作为一条 **Record** 落进本地 SQLite：可搜索、可打标签、可单条复制、可整库导出成 markdown 或 Anki CSV（每个 Gloss 一张卡）。**历史库同时就是缓存**——同一段文本、同一等级、同一 provider profile、同一提示词版本只生成一次。

`plainly` 是瘦 CLI：`echo … | plainly` 直接出 markdown，`plainly explain file.md` 是长文本的正路，退出码可脚本化。默认走云端（快且准、默认关闭思考），本地模型是离线备选，并且**面板上固定写着它可能自信地错**——原文常显、一键换云端重新生成。剪贴板被密码管理器打上标记时，内容既不发送也不入库，面板明说。

v0 的承诺：**Linux 一等公民**（niri / wlroots 系完整；GNOME 有据可查地降级），core 保持跨平台以便 v1 接 macOS 与 Windows。

## User Stories

### 触发与取词

1. 作为读英文的桌面用户，我想要按一次合成器快捷键就把剪贴板里那段难英语变成解释，以便不打断阅读节奏。
2. 作为 niri 用户，我想要一条可以直接粘进配置的 `spawn` 片段，以便几分钟内接上而不需读文档。
3. 作为不愿常驻任何后台进程的用户，我想要按键才拉起面板、关掉即消失，以便不占内存也不占端口。
4. 作为同一段没换就再按一次键的用户，我想要第二次按键重新读剪贴板并刷新面板，以便"复制新一段 → 再按一次"原地换内容。
5. 作为已经打开面板又按了一次键的用户，我想要屏幕上始终只有一个面板，以便不会出现两份叠在一起的解释。
6. 作为 GNOME 用户，我想要复制后按键仍然能读到剪贴板（面板取得焦点即可），以便在不适配 data-control 的桌面上也能用。
7. 作为 GNOME 用户，我想要"复制自动弹"开关变灰并附一行可操作的说明，以便我知道换个桌面就能用，而不是以为功能不存在。
8. 作为 X11 会话用户，我想要被明确告知不支持而不是静默失败，以便我不浪费时间去排查。
9. 作为打开"复制自动弹"的用户，我想要它只在具备 data-control 的桌面上生效、默认关闭、且需要我明确开启常驻，以便它不会偷偷把网络请求打出去。

### 面板

10. 作为学习者，我想要原文与解释同屏、原文常显，以便我自己核对模型的解释。
11. 作为用本地模型的用户，我想要面板正文下方固定一条"本地模型可能自信地错，请对照原文或换云端重新生成"的提示，以便不把错的习语解释记成对的。
12. 作为用本地模型的用户，我想要一键"重新生成"，以便纠正本地模型的错解。
13. 作为用户，我想要面板显示这条解释出自哪个 provider 与模型（provenance chip），以便判断该信几分。
14. 作为学习者，我想要 Gloss 按"最挡路的先解释"排序，以便先解决最卡的地方。
15. 作为用户，我想要 Grammar 为空时该节显示"本段不需要"而不是整节消失，以便区分"没有结构难点"与"没生成"。
16. 作为用户，我想要分节可折叠，以便长解释也能一眼扫完。
17. 作为用户，我想要加载态里原文先出现，以便知道正在解释的是哪一段。
18. 作为用户，我想要出错时看到人话原因、是否已重试、以及"剪贴板内容未变、什么都没存"，以便决定是原样重试还是换 provider。
19. 作为用户，我想要加载、结果、出错、拒绝四种状态都能关掉面板，以便不会留下一个关不掉的浮层。
20. 作为用户，我想要面板不抢键盘焦点，以便我在别处打字不被打断。
21. 作为用户，我想要面板位置可选四角或跟随当前显示器，以便它不挡我正在看的东西。
22. 作为用户，我想要"自动消失"是一个开关、时长是另一个设置（默认关 / 打开后 20 秒），以便"关"只有一种写法。
23. 作为用户，我想要面板在 5 秒内没能成功绘制就自己退出，以便它不会持有一个看不见的浮层挂在那里。
24. 作为用户，我想要面板里的 ✕ 一直可用，以便默认配置下我总有一个确定的关闭手段。
25. 作为长输入用户，我想要多块结果按原文顺序堆叠在一个可滚动面板里，以便不会漏看后面几块。
26. 作为长输入用户，我想要超过 5 块时被明确拒绝并被告知改用 CLI，以便一次粘贴不会触发几十次请求和几十条记录。
27. 作为用户，我想要界面文案是中文，且集中在一份可替换资源里，以便将来能翻译而不必重写。

### 解释内容与等级

28. 作为学习者，我想要改写是在我这个等级上的常用英语，而不是逐词替换，以便读完能懂原意。
29. 作为学习者，我想要 Gloss 只解释真正的 Blocker、且不比被解释的表达更难，以便不被更难的释义卡住。
30. 作为学习者，我想要习语、搭配、语域（含反讽与轻描淡写）被当作 Blocker 处理，以便不被字面意思骗过去。
31. 作为学习者，我想要结构难点（倒装、从句归属不明）出现在 Grammar 节而不是被塞进 Gloss，以便知道难在句子的形状。
32. 作为学习者，我想要母语翻译自然、不逐词，以便确认自己理解对了。
33. 作为中级学习者，我想要把等级设成 A2 时真的得到更简单的改写，以便这个旋钮有效。
34. 作为用户，我想要设置里看到每个等级的含义，以便知道选 A2 与选 B2 的差别是什么。

### 提示词

35. 作为用户，我想要出厂提示词随应用更新持续改进、而我的改动不丢，以便不必手工合并。
36. 作为用户，我想要只能往提示词后面追加规则、不能删基础规则，并且界面说清原因，以便我的历史仍然可比。
37. 作为用户，我想要改了提示词之后旧记录原样渲染、只有我显式要求才重跑，以便改设置不销毁旧答案。
38. 作为用户，我想要"重新生成"能绕开缓存，以便我能修正一条烂答案。
39. 作为用户，我想要提示词没通过契约时被明说并给一键"改用出厂默认重试"，以便它不静默回退。

### Provider

40. 作为用户，我想要内置预设（DeepSeek / OpenAI / llama.cpp / Ollama / LM Studio）加自定义 base URL 与 model id，以便接任何 OpenAI 兼容端点。
41. 作为用户，我想要配置层面能选模型而不只是选端点，以便本地一个端口下的多个模型都能用。
42. 作为用户，我想要应用自己试一次就知道这家 provider 能不能强制 schema 并如实告知，以便我知道哪些 provider 敢承诺契约、哪些只是尽力而为。
43. 作为用户，我想要本地运行时靠探测常见端口发现，而不是靠我猜端口，以便接上就能用。
44. 作为用户，我想要 API key 按环境变量 > OS keyring > 仅本次会话内存的优先级解析，且绝不落明文，以便我的 key 不被写进磁盘。
45. 作为用户，我想要默认 provider 是云端且默认关闭思考（约 1.3 秒），以便"按键看一眼"是快的。
46. 作为用户，我想要"详尽档"（开启思考）能在设置里打开、默认关，以便我偶尔要更细的语法说明时能拿到。
47. 作为用户，我想要 429/5xx 自动退避重试、不受支持的参数降级并重探，以便偶发问题自己消化。
48. 作为用户，我想要同一错误重复出现时立即停止而不是白重试，以便不花三倍时间拿同一个错。
49. 作为脚本作者，我想要"provider 生成失败"与"我们主动拒绝"是不同的退出码，以便脚本能分开处理。

### 历史、搜索与标签

50. 作为学习者，我想要每次解释自动落进本地历史，以便之后回看。
51. 作为学习者，我想要同一段文本第二次查询直接命中历史而不是再花钱，以便重复查询零成本。
52. 作为换了模型的用户，我想要切换 provider / model 之后不会命中旧模型留下的烂答案，以便"换云端重新生成"真的有效。
53. 作为用户，我想要历史按最近查看排序、再次命中时更新该时间，以便最常用的排在前面。
54. 作为用户，我想要搜索只搜英文字段，并在搜索框下明说"中文翻译暂不可搜"，以便我不把限制当 bug。
55. 作为用户，我想要标签手动加、在详情里编辑、在列表里当筛选 chip，以便我自己整理。
56. 作为用户，我想要列表行显示提示词版本与 provider / 模型 / 等级 / 时间，以便同一段落的多版本不被当成重复条目。
57. 作为用户，我想要能硬删单条、全量清除需要二次确认，以便清理不留坟场。
58. 作为用户，我想要本地库不加密，以便我不会因为忘记密码丢掉全部历史。
59. 作为用户，我想要同一段落在新等级下是一条新记录而不是改写旧的，以便改设置不影响旧记录。

### 导出

60. 作为学习者，我想要把单条复制成 markdown、把全部导出成单个 markdown 文件，以便贴进笔记。
61. 作为 Anki 用户，我想要每个 Gloss 一张卡（正面 expression、背面 gloss、原句做上下文）的 CSV，以便直接导入复习。
62. 作为用户，我想要一份原始 CSV 给表格软件，以便做别的用途。
63. 作为用户，我想要导出入口分两处（详情里的单条、设置里的三条全局），以便不必在每条记录上挂三个按钮。

### CLI

64. 作为脚本作者，我想要 `echo … | plainly` 直接得到 markdown，以便接进任何管道。
65. 作为脚本作者，我想要 stdout 只出产物、stderr 出人类信息，以便管道输出干净。
66. 作为脚本作者，我想要 `--format json` 拿到含原文与元数据的结构化产物，以便程序消费。
67. 作为脚本作者，我想要 `--regenerate` 绕开缓存，以便修正一条答案。
68. 作为脚本作者，我想要固定语义的退出码（0 成功 / 1 生成失败 / 2 用法错误 / 3 未配置 / 4 主动拒绝），以便可靠分支。
69. 作为脚本作者，我想要 `explain` 能吃文件，以便处理长文且不受面板 5 块上限限制。
70. 作为脚本作者，我想要长输入时先被告知"将执行 N 次请求"、且逐块进度写到 stderr，以便知道要等多久。
71. 作为脚本作者，我想要某一块失败时其余仍产出、退出码反映失败，以便一次跑完不必全部重来。
72. 作为脚本作者，我想要无输入且 stdin 是 TTY 时报用法错误，以便它不静默阻塞等输入。
73. 作为 headless 用户，我想要 CLI 不依赖 GTK/webkit 就能构建运行，以便在 CI 与无图形环境里使用。
74. 作为 dotfiles 用户，我想要 `config path` 打印配置文件路径，以便把它纳入版本管理。

### 配置与首次运行

75. 作为用户，我想要配置是 TOML（可人编、可 diff）、记录在 SQLite，以便两者各用合适的形式。
76. 作为同时用 CLI 与 GUI 的用户，我想要配置写入是原子的、外部改动会被检测到，以便两个进程不互相吃掉修改。
77. 作为用户，我想要能力探测结果放在可重算的缓存目录，清缓存不丢我的选择，以便人和机器的结论不打架。
78. 作为首次运行的用户，我想要窗口直接开在设置页的空状态（没 key / 没可用 provider），而不是走一段一次性引导，以便我以后随时能回到这一屏。

### 敏感内容

79. 作为用户，我想要剪贴板被打上密码管理器标记时应用不发送、不入库并明说，以便不会把密码发到云端。
80. 作为用户，我想要这条规则与 provider 无关（本地也不放宽），且不给"坚持解释"的出口，以便安全规则可以被推理。
81. 作为用户，我想要规格写明"不遵守该约定的密码管理器不会被保护"，以便我不高估覆盖面。

### 开发环境

82. 作为贡献者，我想要 `nix develop` 给出锁定且可复现的环境（含 gtk-layer-shell、wayland backend、C 编译器），以便新克隆就能构建。
83. 作为贡献者，我想要仓库里带一张占位图标，以便第一次构建不会 panic。

## Implementation Decisions

### 1. 范围与平台承诺

- **v0 = Linux 一等公民 + core 跨平台**。桌面交互**无法跨平台统一**，因此能力（data-control、layer-shell）在**运行期探测**，不写死进文档。
- **niri / wlroots / Smithay 系**：完整路径——无焦点 layer 面板 + data-control 取词。
- **GNOME（Mutter）**：有据可查的降级——既无 data-control 也无 wlr-layer-shell，面板退化为**取得焦点的普通窗口**，此时 GTK 剪贴板 API 可用（两件事一起退化，不是两个独立降级）。
- **X11：v0 明确不支持**，写进规格而不是留白。X11 上没有 layer-shell，抓键要另写一套路径，而它是退场中的会话。CLI 与图形无关，在 X11 下仍可用。
- **三个二进制**：`plainly`（瘦 CLI，只依赖 core）、`plainly-panel`（独立 layer 面板进程）、`plainly-desktop`（Tauri 主窗口：历史 / 设置 / 导出）。
- **macOS / Windows 是 v1**；core 不得依赖 GTK / webkit / Wayland，以便届时接入。
- **本地模型不是卖点**，只是 provider 之一。

### 2. 工作区与 crate 边界

- 一个 Cargo workspace，四个 crate：`plainly-core`（领域逻辑、provider、存储、提示词）、`plainly-cli`、`plainly-panel`、`plainly-desktop`。
- **`plainly-cli` 不得依赖 GTK / webkit**，且必须能单独构建（`cargo build -p plainly-cli`）——否则"CLI 不依赖图形库"只是空话，headless 与 CI 环境会直接跑不起来。
- `plainly-core` 不引入 GTK / Wayland 依赖：**平台能力以数据形式注入**（剪贴板内容与 MIME hint 列表、桌面能力探测结果），判定与降级逻辑留在 core 里，因此可以在无图形环境里测试。

### 3. Explanation 契约

- 一个 **Explanation 对应一个 Passage**（一段话）。长输入在**段落边界**切分，每块各自成篇——不是把一个产物拆成多次调用；一次调用才能让改写、Gloss、翻译互相看得见。
- **模型只产出内容四件套**——`comprehensible`、`glosses[]`、`grammar|null`、`translation`。**原文与全部元数据**（Level、Native Language、provider、model、thinking、时间戳、版本）由应用附加。理由：原文权威副本在应用手里，回显等于给模型一次静默篡改的机会；Level 与 Native Language 是应用的设置，不是模型的观察；输出越小，本地小模型的遵从率越高。
- **`glosses` 是对象数组 `[{expression, gloss}]`**，不是字典（OpenAI strict 不支持 `patternProperties`），数组还能保序。**不带 `why`**（那是过程不是产物）。
- **wire schema 不落库**——它与 artifact 版本同生共死。
- **两个版本号独立演化**：`artifact_version`（数据模型，随 Record 入库；v0 = `1`）与 `prompt_version`（产出它的提示词，见第 5 节）。
- 契约的 schema 形状（来自原型 `bench/schema.json`，它已在 llama.cpp 路径上跑通 12/12，直接作为 v0 的契约）：

```jsonc
{
  "type": "object",
  "additionalProperties": false,
  "required": ["comprehensible", "glosses", "grammar", "translation"],
  "properties": {
    "comprehensible": { "type": "string" },
    "glosses": {
      "type": "array",
      "items": {
        "type": "object",
        "additionalProperties": false,
        "required": ["expression", "gloss"],
        "properties": { "expression": { "type": "string" }, "gloss": { "type": "string" } }
      }
    },
    "grammar": { "type": ["string", "null"] },
    "translation": { "type": "string" }
  }
}
```

- **硬约束（ADR-0001，不得违反）**：schema 里**不出现任何长度 / 模式 / 数值上下界**——不加 `maxItems`/`minItems`/`minLength`/`maxLength`/`pattern`/`format`/`minimum`/`maximum`。OpenAI strict 模式会因此校验失败；llama.cpp 会因矛盾下界（`#29462`，未修）被一次请求 OOM 杀掉。需要"3–5 条 Gloss"这类约束时，靠**提示词 + 校验 + 重试**表达，或只用 `maxItems` 且验证 schema 后再发。可选字段写 `type: ["string","null"]` 且**仍列进 `required`**；根节点不能是 `anyOf`。

### 4. 渲染

- markdown 渲染**逐字复刻原型 `comprehensible-english/SKILL.md` 的五节形状**：`### Original` / `### Comprehensible English` / `### Key Help`（`- \`expr\` → gloss`）/ `### Grammar`（仅当需要时出现，位于 Translation 之前）/ `### Translation`。用户看不出来它来自 JSON。
- **渲染器是纯函数**，CLI、导出与 UI 共用同一结构；UI 的节标题可本地化（内容仍固定英文）。
- **`grammar` 为 null 时的两种表现，取决于表面**：CLI / 导出的 markdown **省略该节**（原型行为）；面板**显示"本段不需要"**（用户要能区分"没有"与"没生成"）。
- 面板正文顺序固定：原文（常显、暗色斜体、小一号）→ 改写 → Gloss 紧凑列表 → Grammar → 翻译（绿色）。

### 5. 提示词模型

- **有效提示词 = 出厂默认（不可变、随版本更新）+ 用户附录（append-only）**。上游改进因此能到达用户，用户改动不丢；附录**只能加不能删**基础规则——对契约而言增加比删除安全，基础保持 artifact 的定义，否则各人的历史不再可比。用户若要反制某条基础规则，只能写一句相反的规则去覆盖；**这个能力弱点写进规格，不假装不存在**。
- 出厂提示词的起点是标定过的 **v6-synthesis**（不编造 / 保专有名词 / 反讽规则 / 显式 grammar 措辞 / "必须是真改写"），并**升级为 v7：内联等级描述表**——`{{LEVEL}}` 不能只代入标签，要代入"标签 + 含义"。依据是实测：只发标签时 3/8 个相邻等级对产出逐字相同的解释，内联描述后降到 1/8，A2 平均词长 4.29→4.05、与原文相似度 0.460→0.395。
- **可调的结构化参数只有两个**：等级与母语（都进 Lookup Key）。**输出小节开关是显示层开关**——提示词照旧请求全部四个键，开关只控制显示；因此它属于 `[app]` 的显示偏好，**不进 Lookup Key**，切换即时、不重新生成、不碎片化缓存。
- **不做**：片段注册表、按小节的 schema 变体、UI 内多套提示词管理。
- **v7 的 C1 描述不得与"必须是真改写"冲突**（v6 的 C1 描述 "keep most of the original structure" 与硬规则打架，后者赢，这很可能就是 B2 与 C1 无法区分的原因）。
- **`prompt_version` = 有效提示词的内容哈希（派生，不是人声明的）**：`SHA-256(出厂默认 + 用户附录 + 等级描述表)`，**占位符不替换**（等级与母语已是 Lookup Key 的独立分量）。等级描述表必须计入哈希——若它留在代码里，"改一句描述"会改变输出却不改变版本，正好制造陈旧命中。由此，票据 08 那条"内容改了必须升版本"从**纪律**变成**结构保证**。
- Record 里**同时存人类可读标签**（如 `v6-synthesis`）：哈希是"真的版本"，标签是"给人的名字"；**不存提示词正文**，所以旧记录永远可渲染。
- **迁移语义：旧记录原样渲染，重跑只能显式**。改 Level 不触碰旧记录——同一段落在新等级下是新查询（新 key → 新记录）。明确否掉"用新提示词静默重跑全部历史"。
- **兜底：绝不静默回退**。契约失败（走完重试之后）→ 明说"你的提示词没通过契约"并给一键"改用出厂默认重试"；Record 里记的是真正产出它的那个提示词。不做保存期探针，也不在保存时阻断。
- **代价（诚实记下）**：应用更新改动出厂提示词 → 所有段落 hash 变化 → 每段下次查询各重新生成一次。这是正确行为，但历史里同一段落会**同时存在多个 prompt 版本的记录**——这是特性（可比较），UI 必须能区分（见第 13 节）。

### 6. 输入切分与长文本

- **度量**：空白切分的词数。**阈值 150 词**（约 900 输出 token、约 4.5 秒）。这个数字的根据是"能忍几秒"，不是"能不能放下"——先撞墙的是输出侧（输出 token ≈ 6 × 输入词数、耗时 ≈ 0.03 秒/词、Gloss ≈ 每 10 词 1 条；190 词 = 1143 token / 5.7 秒，而输入只用掉约 260 token，本地上下文是 16384）。
- **切分规则**：段落边界优先；**单个段落自身超过 150 词时降到句子边界**。
- **一块一条 Record**（符合"一个 Explanation 对应一个 Passage"），**幂等键按块生效**——只有变化的那块需要重新生成。代价：一次粘贴产生 N 条历史记录，可接受且可单独删。
- **面板硬上限 5 块**（约 750 词）：超过则**拒绝**并提示改用 CLI 或先拆分。上限掐掉的是"粘一整篇文档 → 几十次请求、几十条记录、几十秒"这个失败模式。**CLI 不继承该上限**——它是长文本的正路。
- **`max_tokens` 必须 ≥ 约 1200**（实现取默认 2048），与 150 词阈值**成对**：否则块会被截断，而截断必然导致 JSON 解析失败，进而触发出错误处理与重试，表现成"长输入总是失败"，把根因藏在看起来像提示词问题的地方。**改阈值或改 max_tokens 时必须一起看。**

### 7. Provider 层

- **配置面 = 预设 + 自定义**：内置已知 provider 的预设（endpoint + 已知能力形态），同时允许自定义 base URL 与 model id。provider 的差异**不止 base URL**，所以配置面必须能选**模型**，不只选端点。
- **能力探测 = 试一次 + 缓存 + 如实降级**：首次配置某 provider 时发一个极小探针请求（`json_schema` 试探 + 读模型列表 / 上下文），结果缓存进 `appCacheDir`。不支持或探测失败 → 降级为"只能尽力而为"（`json_object` + 校验 + 重试）并**如实告知**用户。**明确拒绝静态能力表**（同一家 API 会变：DeepSeek 的 `json_object` 可用而 `json_schema` 不可用）。缓存不设 TTL；在 4xx 参数不受支持、手动重探、endpoint / model 改动时失效。
- 探测信号是干净的：DeepSeek + `json_schema` → HTTP 400（`This response_format type is unavailable now`）、同端点 + `json_object` → 200；llama.cpp + `json_schema` → 200。
- **默认端点**：云端 `deepseek-flash` + **默认关闭思考**；**本地不猜端口**，探测常见端口（3060 / 11434 / 8080 / 1234），把发现的运行时与**每个模型的 `loaded|unloaded` 状态和上下文长度**列进配置页让用户点选（本地 router 的有用端点是 `/v1/models`，不是 `/props`）。
- **"思考"建模为能力 `thinking: on | off | unsupported`，默认 off**——它是请求参数而不是模型选择，接口必须表达它，否则以后加不了"详尽档"。规范写法 `{"thinking":{"type":"disabled"}}`；`{"thinking":false}` 是 422；`{"enable_thinking":false}` 静默无效；思考态下 `temperature` / `presence_penalty` / `frequency_penalty` **全部静默失效**。
- **各 provider 的调用面硬要求**：
  - **llama.cpp**：必须发**嵌套**的 `response_format.json_schema.schema`；扁平写法会被**静默忽略**并降级为任意对象且不报错。sidecar 应带 `--api-key` 跑在 loopback（否则 `#29462` 的 OOM 路径可达）。
  - **LM Studio**：`{"type":"json_object"}` 会 400；读 `content`，为空时回退 `reasoning_content`（Qwen3.5 系列已知命中）。
  - **OpenAI**：解析前先查 `message.refusal` / `content[].type == "refusal"`，并处理 `status: "incomplete"`。
  - **Ollama**：优先原生 `/api/chat` + `format`，`/v1` 的 `response_format` 作回退；关 thinking 要求 ≥ 0.31.2；`num_ctx` 只能走 Modelfile 或 `OLLAMA_CONTEXT_LENGTH`。
  - **DeepSeek**：无 schema 强制，归入"提示词 + 校验 + 重试"档，且要处理空 content。
- **错误分类与重试（四类，各走各的路）**：

  | 类型 | 处理 |
  |---|---|
  | 输出畸形（JSON 解析 / 校验失败） | 重试，最多 2 次额外 |
  | **同一错误重复**（第 2 次与第 1 次完全相同） | **立即停**——判定为系统性漂移，重试无用 |
  | HTTP 4xx 参数不受支持 | 不重试；**降级能力并重新探测** |
  | 429 / 5xx / 超时 | 退避重试，最多 2 次额外，间隔约 1 秒 / 4 秒 |

  单请求超时 60 秒（覆盖本地冷启动 7.2 秒）。**推理模型的 token 预算**：思考态下 `reasoning_tokens` 可占 completion 的 90%+，`max_tokens` 必须按思考预算给足，否则长句被截断成畸形输出，再被重试逻辑误判成"畸形"。
- **v0 不做流式**，接口留位置。理由：流式与"必须等完整 JSON 才能校验"天生冲突——要么边流边呈现未经验证的内容（等于把"自信但错"提前递给用户），要么等完整产物再渲染（那就没有流式）；而等待只有 1.3–1.7 秒。

### 8. 配置与密钥

- **配置走 TOML 文件，记录走 SQLite**：配置在 config 目录（`appConfigDir()`），历史库在 data 目录（`appDataDir()`），能力探测缓存在 `appCacheDir()`（可重算，不与人的选择竞争）。
- **一个配置文件，三段**：`[app]`（人的选择：当前 provider、等级、母语、导出格式、UI 语言、输出小节显示开关、面板角与显示器、自动消失开关与时长、"复制自动弹"开关）、`[providers.<name>]`（endpoint、model、thinking）、`[prompts]`（提示词数据：出厂默认随应用更新，用户附录与等级描述表为数据）。
- **边界**：**存储归配置 / 记录归历史库 / 提示词内容归提示词段**。等级与母语的**值**存在 `[app]`，但它们的**含义、默认值、如何喂进提示词、版本与迁移**归提示词模型；每条 Record 盖上"当时用的值"。
- **identifier 定为 `dev.plainly.app`**（决定配置 / 数据目录名），**不另造 `~/.config/plainly/`**。面板的 GApplication id 是 `dev.plainly.panel`。
- **项目级覆盖 v0 不做**（单用户桌面应用没有"项目"概念）；格式留出"从 cwd 向上查找"的余地。
- **密钥三级**：环境变量 `PLAINLY_<PROVIDER>_API_KEY` > OS keyring > **仅本次会话内存**（退出即失，明确告知）。**拒绝明文文件**，也**拒绝直接禁用云端**（headless 会被彻底挡住）。keyring 在 Linux 走纯 Rust D-Bus（`zbus-secret-service`），flake 里不需要 libsecret。
- **CLI 与 GUI 会同时写同一份配置**——认下这个代价，因此写入必须**原子**（临时文件 + rename）并做**外部修改检测**（mtime）。
- **SQLite 以 WAL 打开**，面板与主窗口各持连接，设 `busy_timeout`：多进程并发读 + 串行写。

### 9. 历史库、Lookup Key 与导出

- **存储形态：关系化**——`records` + `glosses(record_id, ord, expression, gloss)`。理由：Anki 导出的天然单位就是单个 Gloss（一条 SQL 出卡）；FTS5 可直接索引 `expression` / `gloss`；`ord` 明确保序。不用 JSON1 存 Gloss（那会把"按表达检索"变成解析问题）。
- **Record 字段**：原文、Explanation 四件套、等级、源语言与母语、provider、model、thinking、时间戳（created / generated / last_seen）、`artifact_version`、`prompt_version` 哈希、提示词人类标签、Lookup Key。
- **Lookup Key**（历史库兼任缓存的机制，来自原型讨论的收紧版）：

  ```
  lookup_key = SHA-256(
      归一化(passage) + level + source_language + native_language
      + prompt_version + provider + model + thinking
  )
  ```

  - **归一化只做首尾空白与换行风格（CRLF→LF）**；内部空白有意义，原文逐字入库不归一化。
  - **SHA-256，不用 64 位哈希**——碰撞意味着悄悄返回错的解释，成本不对称。
  - **key 必须含 provider profile（provider + model + thinking）**，否则用户拿到烂答案后切到云端会从缓存取回同一个烂答案。
  - **key 含 `prompt_version`，不含 `artifact_version`**——前者变了答案该变；后者只是形状变了，放进 key 会让每次应用更新碎片化整个缓存。
  - **命中复用同一行**（不插新记录）：更新 `last_seen`；**历史按 `last_seen` 排序**。**不记 `lookup_count`**（不做 SRS）。
  - 主键仍是整数 id，`lookup_key` 上建 UNIQUE 索引（便于 `glosses` 外键）。
- **"重新生成"语义**：**原地覆盖** Explanation，更新 `generated_at`；保留 `created_at` 与 `last_seen`。
- **源语言 v0 不检测**：`source_language = "en"` 是配置常量，字段照样入库（溯源 + 未来多语言源），**不做检测**（那要么加一次模型调用，要么分叉缓存）。
- **搜索**：两张 FTS5 表——一张索引 Record 的 `passage` + `comprehensible`，一张索引 Gloss 的 `expression` + `gloss`；查询取并集去重后按 `last_seen` 排序。**`translation` 不进索引**（tokenizer 是 per-table，中文要单独一张 trigram 表；升级路径是纯增量）。`grammar` 同样不进索引。规格写明"**中文翻译 v0 不可搜**"这个事实，而不是让它看起来像隐藏缺陷。`rusqlite` 的 `bundled` feature 默认带 FTS5（含 trigram），系统无需安装 sqlite。
- **生命周期**：历史列表可单条**硬删**；全量清除要二次确认；**不加密**；标签 v0 只做**手动**；**原文必须总是入库**——**唯一例外是被判为敏感的剪贴板内容**（见第 11 节），这是有意的例外，规格点明，否则实现者会以为"总是入库"是绝对的。
- **导出三形态**：
  - **Markdown**：单文件、按 Record 分节；每节标题带日期 + 等级 + provider / 模型 + 提示词标签，正文用五节渲染。
  - **Anki CSV**：**每个 Gloss 一行**；正面 = `expression`，背面 = `gloss`，上下文 = 该 Record 的原文；另附等级 / 母语 / provider / 模型 / 提示词标签列便于筛选。**不做 `.apkg`**（那是实现半个 Anki 内核，而 Anki 本来就支持 CSV 字段映射）。
  - **原始 CSV**：每个 Record 一行，Gloss 以 `expression → gloss` 多行文本放在单个单元格里（给表格软件）。

### 10. CLI 契约

- **四个顶层子命令**，**无子命令时默认走 `explain`**（`echo … | plainly` 直接可用）：

  | 子命令 | 覆盖 |
  |---|---|
  | `explain` | 输入 stdin / 文件 / `--clipboard`；`--format markdown\|json`；`--regenerate` |
  | `history` | `list` / `show <id>` / `search <query>` / `delete <id>` / `clear` / `export markdown\|anki\|raw` |
  | `providers` | 探测本机常见端口并列出运行时；显示当前 provider、模型、thinking 与**能力探测结果**；`probe [name]` 强制重探；`key set\|clear <name>`（写 keyring，绝不落明文） |
  | `config` | `path`（打印配置文件路径）/ `show` / `set <key> <value>` |

- **I/O 契约**：**stdout 只出产物，stderr 出人类信息**。
- **退出码**：`0` 成功 · `1` provider / 生成失败 · `2` 用法错误 · `3` 未配置（没有 key 或没有可用 provider）· **`4` 主动拒绝**（敏感内容）。4 的存在是因为脚本要能分开"provider 失败"与"我们主动拒绝"。
- **`explain` 在无输入且 stdin 是 TTY 时报用法错误**，不默默阻塞等输入。
- **长文本批次行为（规格层补定）**：切分后**串行**按顺序执行；开始前向 stderr 报"将执行 N 次请求"；每块完成向 stderr 报进度；产物按原文顺序写到 stdout（markdown 以空行分节）。**某块失败时其余块继续**，已产出的部分保留，退出码为 `1`；整份输入被判为敏感时**不产生任何产物**，退出码 `4`。**CLI 不继承面板的 5 块上限。**
- **`--format json` 的产物形状**：一个 JSON 文档 = Artifact，含原文与 Explanation 四件套与全部元数据（等级、源 / 母语、provider、model、thinking、`artifact_version`、`prompt_version` 哈希与标签、时间戳）；多块时是这些 Artifact 的数组，顺序同原文。
- 桌面端没在跑时，`plainly explain` 不需要桌面端；面板则由合成器键绑直接 spawn（第 12 节）。

### 11. 敏感剪贴板

- **判据（两步、纯本地、零网络）**：① 类型列表里出现 `x-kde-passwordManagerHint`；② 它的取值是 `secret`。**两者同时成立**才判定为敏感。
- **判定后**：**不发送、不入库、面板明说，且不给"坚持解释"的出口**。代价不对称：误发一次很难挽回，少解释一段几乎无损。
- **检查在 core 一处兜住**：面板、CLI、以及"复制自动弹"都只显示结果，不各自实现——界面层各写一遍迟早漏一处，而漏掉的那一处正好是泄露发生的地方。平台侧只负责把 MIME hint 列表**作为数据**交给 core。
- **不做启发式兜底**（高熵串 / 短串 / 无空格）：会同时产生假阳性与假阴性，最糟的是给人"有防护"的错觉。**记为刻意不做，而不是漏做。**
- **本地 provider 不放宽**：依赖某个设置的安全规则用户没法推理，而"解释一段密码"没有正当需求值得开例外。
- **局限写进规格**：**不遵守该约定的密码管理器不会被保护。** 文件与 stdin 输入没有类型标记，因此这条判据只覆盖剪贴板路径。

### 12. 面板（`plainly-panel`）

- **进程形态**：**独立 GTK + gtk-layer-shell 进程**，`GtkApplication`（id `dev.plainly.panel`）。**不能**用 Tauri 做面板：宿主机实测表明 Tauri 能**创建** layer 表面却**画不出任何内容**（连直接画在窗口上的纯色背景都不上屏），根因未定位但决策不依赖它（追根因别从 GtkApplication 那条线查）。
- **触发**：**合成器键绑直接 spawn 面板进程**——`spawn "plainly-panel" "--clipboard"`。面板自给自足（自己用 data-control 读剪贴板、调 core、显示），因此**没有任何东西需要常驻**。最小 niri 片段随规格交付；`spawn` 不走 shell、不展开 `~`；`hotkey-overlay-title` 让它在快捷键浮层里有名字。niri 的 `spawn` 修饰键 bug **不需要应对**（面板 `keyboard_mode=NONE`，根本不接收键盘事件）。
- **单实例与重入**：`GtkApplication` 白送单实例（application uniqueness + `activate`），只需在 `activate` 里**复用已有窗口**。**`activate` 复用语义 = 重新读剪贴板并刷新**——按第二次键的人几乎总是复制了新的一段；真是同一段时 Lookup Key 会命中缓存，成本近零。
- **取词必须走 data-control**：无焦点的 layer 表面上 `gtk_clipboard` **直接失败**（实测返回空），而 data-control 读得到。实现用 Rust 绑定直接绑协议；外部 `wl-clipboard` 命令只作兜底（那时才查版本 ≥ 2.3.0）。
- **能力探测**：查 `ext_data_control_manager_v1` / `zwlr_data_control_manager_v1` 是否存在，结果**必须驱动行为**（不是只写日志）。与 provider 能力探测严格区分：这里探的是**桌面环境**的能力。
- **降级**：没有 data-control → 面板退化为**会取得焦点的普通窗口**（GNOME 上 layer-shell 也没有，两件事一起退化），此时 GTK 剪贴板可用。
- **外观与内容**：固定标题栏（标题 + **provenance chip** + 复制 / **⟳ 重新生成** / ⤢ 打开历史 / ✕）+ 正文密度取"原文常显 → 改写 → Gloss 紧凑列表 → 翻译"；分节可折叠；`grammar` 为 null 时该节显示"本段不需要"。**本地 provider 时正文下方固定一条核对提示**（"本地模型；它的习语解释可能自信地错——请对照上方原文，或 ⟳ 换成云端重新生成"）。面板宽约 470px。
- **不抢焦点**：`keyboard_mode=NONE`，保持已验证过的属性（无焦点、不进合成器的窗口列表）。
- **退出路径（面板只有 ✕ 一条正常出路）**：
  - **✕（固定位置）**；
  - **渲染看门狗**：进程在 **5 秒**内没有成功绘制就自己退出——覆盖病态情形（曾有一次面板从未上屏、也从未退出，挂了 23 分钟持有一个 overlay 表面）；正常路径永不触发；
  - **自动消失：默认关**；打开后默认 20 秒。**开关与时长是两个独立键**（不要用时长 `0` 表示"永不"——"关"已经有开关，两种写法迟早矛盾）。
  - **没有"点外侧关闭"**：Wayland 的隔离模型让 layer 表面看不到落在别处的点击；要支持就得加一个更低图层的全屏输入捕获面，它会拦截所有点向其他窗口的点击并吃掉第一次外侧点击，与"不抢焦点的旁路表面"这个性格相反，不划算。
  - 代价诚实记下：**默认配置下 ✕ 是唯一出路**——面板宽 470px 且不抢焦点，不打断打字但会遮挡左上角内容；这正是看门狗值得存在的原因（不能出现"唯一出路依赖面板自己渲染成功"这个单点）。
- **退出实现陷阱**：**必须走 `g_application_quit()`**——`gtk_main_quit()` 管不了 `GApplication` 的主循环（真实事故的来源）。
- **位置**：四个角 + 跟随当前显示器，两个 `[app]` 键。**角是分辨率无关的**（换分辨率 / 换显示器不会把面板丢到屏幕外），这是它优于自由坐标的主要理由。**不做自由拖动**：成本不在代码量（约 50–100 行）而在四个配套问题（拖动与按钮的交互仲裁；位置存什么才能在换分辨率 / 缩放 / 显示器后仍合理；多显示器要换输出并用该输出坐标系重新锚定；必须配套位置复位）。角设置以约 10% 的成本拿到约 90% 的收益，且位置永远可预测。
- **多块与拒绝态（额外三个状态）**：输入切成多块时**按原文顺序把各块堆叠在一个可滚动面板里**（不做分页：键盘模式 NONE，翻页只能靠指针，堆叠无隐藏状态）；两种拒绝态——**内容被标记为敏感**与**输入过长（> 5 块）**——都要**明说原因**（"这段有敏感标记，未发送也未保存" / "这段太长，请用 CLI 或先拆分"），且**拒绝态同样有出路**。
- **加载态**：原文先可见 + 骨架条 + `explaining…`（首次冷启动 1.3–2 秒，加载态不是可选项）。**出错态**：人类可读原因 + 已重试情况 + **"剪贴板内容未变、什么都没存"**；不做按错误类型分叉的多套界面（分类与重试在 core）。
- **思考开关只在设置里，默认关**：开启思考约 9.8–12.8 秒，在"按键看一眼"里不可用；真想要详尽的人已经有 ⟳ 这个入口。存储归 `[providers.*]`。
- **UI 语言**：中文为主；**界面文案集中成一份可替换资源**（一个 strings 模块），**不引入 i18n 框架**——这是"将来能翻译"与"将来必须重写"的区别，成本近零。markdown 内容仍固定英文。
- **"复制自动弹"（默认关）**：能力不具备时在设置里**灰掉 + 一行可操作说明**（"需要 wlroots 类合成器的 data-control 协议"），**不隐藏**——隐藏会让用户以为功能不存在。**谁持有监听循环（规格层补定）**：票据 07 只定了开关的呈现与默认值，没有定谁在常驻。v0 的实现决定是——开关打开时由 `plainly-desktop` 承担监听（`plainly-desktop --watch`，或主窗口保持运行）；打开它才引入一个常驻进程，默认路径下仍然"没有东西需要常驻"。CLI 与键绑都不依赖它。

### 13. 主窗口（`plainly-desktop`）

- **导航**：顶部标签（历史 / 设置）+ **列表常驻**（左约 330px，含搜索框）+ **详情在右**；列表按日期分组（今天 / 昨天 / 更早）。桌面宽度下分栏天然容纳**同一段落多个提示词版本并排比较**。
- **搜索与标签**：搜索框固定在列表顶部，**只搜英文字段**，其下**一行小字说明"中文翻译暂不可搜"**；标签在**详情里编辑**、在列表里作为**可点击的筛选 chip**；**列表行必须显示提示词版本**（连同 provider / 模型 / 等级 / 标签 / 时间），否则多版本会被当成重复条目。
- **导出入口两处分工**：详情里"复制 markdown / 导出这一条"；设置的数据节里三条全局导出。
- **设置五节**：**语言与等级 / Provider / 提示词 / 行为 / 数据**（与配置分段对齐）。其中多数内容已被定死，本表面只负责放置：等级**必须带含义**显示；"复制自动弹"能力不足时灰掉 + 说明；思考开关只在这里、默认关；提示词附录"只能加不能删"的解释；**面板位置**与**面板自动消失的两个控件**（开关默认关；时长默认 20 秒，仅在开关打开时可用，控件形态取数字输入 + 合理范围）。
- **首次运行 = 设置页的空状态**（没有 key / 没有可用 provider 时窗口直接开在这一屏，两条路本来就是设置页的两个控件），**不做独立引导流**。
- **⤢ 从面板打开历史**：面板 spawn `plainly-desktop`，靠 `tauri-plugin-single-instance` 的 D-Bus 交接复用已有实例；**不开该 plugin 的 `semver` feature**（否则升级后新旧实例互不接管），D-Bus 名随 identifier 走。
- 主窗口是 Tauri 普通窗口，票据 12 的结论只否定"用 Tauri 画 layer 面板"，不影响它。

### 14. 开发环境

- **flake**（`flake.nix` + `flake.lock`）：`flake-utils` + `fenix`（`inputs.nixpkgs.follows = "nixpkgs"`），nixpkgs 锁 `nixos-unstable`，工具链取 `fenix.complete`（cargo / clippy / rustc / rustfmt）。
- **系统列表 v0 只列 `x86_64-linux`**，但结构照参数化的 `mkShell` 函数写，v1 加 `aarch64-darwin` 是两行的事（没人验证的 darwin shell 会腐烂，还会给人"已支持 macOS"的错觉）。
- **环境内容**：fenix 工具链、`pnpm` + `nodejs_24`、`pkg-config`、`gtk3`、`gtk-layer-shell`、`webkitgtk_4_1`、`libsoup_3`、`glib-networking`、`openssl`、`patchelf`、`xdg-utils`、`clang`；环境变量 `GDK_BACKEND=wayland`（**与 readest 相反**——layer-shell 在 XWayland 上不存在）+ `LD_LIBRARY_PATH`。**去掉** gstreamer 全家桶、Android/iOS 工具与 playwright。`.envrc` 写 `use flake`。
- **不抄 readest 的 `nixConfig`**（它指向不存在的替代源）；**保留它的教训**：`checks` 不指向应用构建，否则 `nix flake check` 会变成一次完整发布构建。
- **sqlite 的"库"不进 flake**：`rusqlite` 的 `bundled` feature 在编译期编入并静态链接，系统只需 C 编译器；`sqlite3` 命令行工具可选出现在的 devShell（与发布物无关）。
- **CI 推迟到实现阶段**（v0 只定 devShell）；CI 里若跑 CLI 单测，必须用 `-p plainly-cli` 构建。
- **图标**：提交一张占位 `icons/icon.png` 进仓库——缺失时 Tauri 的 `generate_context!` 直接 panic，所以"新克隆能不能构建"取决于它。

## Testing Decisions

**好测试的定义**：只断言**外部行为**——喂进一个 Passage 与一个可编程的假 provider，断言用户/调用者能观察到的东西（产物内容、退出码、stdout / stderr 分流、库里留下的行、提示文案里的关键事实）。不断言内部结构、函数调用顺序、私有字段、SQL 文本或渲染器的中间产物。契约测试的判据是"解析 + schema 校验 + 语义字段"，不是"输出与某个快照逐字节相同"（模型输出不可复现，只有 temperature 0 下的离线 fixture 才可以）。

**两条缝（已与用户确认）**，不新增第三条：

### 缝 A（主）：`plainly-core` 的公共 API

以注入式依赖为测试手段——可编程的假 provider（能按脚本返回畸形 JSON、错字段名、429/5xx、4xx 参数错误、空 content、`reasoning_content` 回退、refusal）、**内存 SQLite** store、注入的剪贴板内容（文本 + MIME hint 列表）、注入的时钟。这条缝覆盖：

- **契约与重试**：解析 + schema 校验；四类错误的各自处理；**"同一错误重复即停"**（脚本让第 1、2 次返回同一个错，断言只调用两次且不重试第三次）；4xx → 能力降级并重探；429/5xx 退避次数与间隔。
- **Lookup Key**：同一 Passage 的空白 / CRLF 差异命中同一 key；内部空白变化**不**命中；level / native / provider / model / thinking / prompt_version 任一变化都产生新 key；**artifact_version 变化不产生新 key**；命中**复用同一行**并更新 `last_seen`；重新生成**原地覆盖**且保留 `created_at` / `last_seen`。
- **切分**：150 词阈值；段落优先；单段超限降到句子；**一块一条 Record**；面板 5 块上限拒绝、CLI 路径不拒绝；块间只有一块变化时只重新生成那一块。
- **提示词**：有效提示词 = 出厂 + 附录；**附录只能追加**；等级描述表改动会改变 `prompt_version` 哈希；占位符**不**参与哈希替换；Record 同时存哈希与人类标签；契约失败时给出"改用出厂默认"的结果而不是静默回退。
- **敏感内容**：MIME 列表含 `x-kde-passwordManagerHint` 且取值为 `secret` 时判定为敏感；只含类型或取值 `public` 时**不**判定；判定后**没有**发生 provider 调用、**没有**写入任何行，且返回一个**可区分的结果**（对应退出码 4）；与 provider 无关（本地也不放宽）。
- **Provider 调用面**：每家的怪癖各一条——llama.cpp 收到**嵌套** `response_format`；LM Studio `content` 空时读 `reasoning_content`；OpenAI 先查 refusal / `status: incomplete`；Ollama 走原生 `/api/chat` + `format`；DeepSeek 只发 `json_object` 且接受校验 + 重试路径；思考参数用规范写法（`{"thinking":{"type":"disabled"}}`）。
- **能力探测与缓存**：探针结果进缓存目录、**不写进配置文件**；4xx 降级后缓存被更新；清空缓存不丢用户的 provider 选择。
- **导出**：markdown 单文件按 Record 分节；Anki CSV **每个 Gloss 一行**且正面 / 背面 / 上下文映射正确；原始 CSV 每 Record 一行；三条导出都有空历史的边界用例。
- **渲染**：五节形状逐字复刻原型示例（含 `grammar` 为 null 时省略该节）；面板模式的"本段不需要"是同一函数的一个变体。
- **历史与搜索**：FTS 命中 `passage` / `comprehensible` / `expression` / `gloss`；`translation` 里的中文**搜不到**（断言为已知事实）；标签筛选；硬删与全量清除；`last_seen` 排序。
- **配置**：原子写；外部修改（mtime 变化）被检测到而不是被覆盖；三段结构与键名；密钥解析优先级（环境变量 > keyring > 会话内存，且**从不**写明文）。
- **CLI 解析层以外的批次决策**：串行顺序、部分失败继续、`--format json` 的多块数组形状。

### 缝 B：`plainly` CLI 二进制（子进程级）

真实二进制 + 临时 XDG 目录（config / data / cache 全指向 tmp）+ 环回上的假 OpenAI 兼容 provider（进程外的小型 stub server）。断言：

- `echo … | plainly` 输出 markdown 五节，**stdout 只有产物**（人类信息在 stderr）；
- `--format json` 是合法 JSON 且含原文与元数据；
- 退出码矩阵：`0` 成功、`1` 生成失败、`2` 用法错误（无输入且 stdin 是 TTY）、`3` 未配置（无 key）、`4` 主动拒绝（敏感剪贴板）；
- `--regenerate` 产生新调用而默认路径命中缓存（第二次不触发任何 HTTP 请求）；
- `explain file.md` 处理超过 5 块的长文本（**不**被面板上限拒绝），先报"将执行 N 次请求"，逐块进度在 stderr，部分块失败时其余仍产出且退出码为 1；
- `config path` 打印的路径确实位于临时 XDG 目录内。

### 先例（prior art）

仓库尚无应用代码，因此先例来自原型：

- **bench harness 是契约测试的现成先例**：12 段覆盖 Blocker 分类的样本文本、可运行的契约 schema、以及"解析 + schema 校验 = `valid`"的判据都可以直接作为 fixture 与断言样式；harness 记录延迟与请求设置的做法，对应"探测 / 调用参数"类测试。
- **原型文档里的两个渲染示例**是 markdown 渲染的金标准（票据 01 已定）。
- 面板与主窗口**不进自动化测试**：GTK 面板的渲染、图层、看门狗与退出路径只留一份 **niri 手测清单**（按键 spawn 出面板 → 焦点不变 → 不抢键盘 → ✕ 可关 → 断开渲染时 5 秒自退 → 多块堆叠 → 两种拒绝态 → 位置设置生效 → GNOME 下降级为普通窗口）。真实 provider 与真实网络调用不进任何自动化测试。

## Further Notes

### 必须传达到实现阶段的诚实记录

- **等级是提示，不是契约**：即使内联了描述，B2 与 C1 在实测中仍无法区分（4.32 vs 4.29 词长；与原文相似度 0.463 vs 0.462）。机制很可能是契约内部自相矛盾（C1 描述"保留更多原结构" vs 硬规则"必须是真改写"），v7 要在不冲突的前提下表达 C1。另外连 A2 也不可靠地最简（p06 / p12 上它的平均词长是三档里最高）。口径是 4 段 × 1 模型 × 每条件一次，方向是**倾向**而非定律。
- **本地 4B = 够用但不可无条件信任**：契约 12/12、热态 1.87 秒、冷启动 7.2 秒（推翻早期"30–60 秒"的估计），但 `bottled it` 讲反、`genteel` 讲错、`grammar` 0/12。**这些是能力边界不是提示词问题**——同一批提示词云端全对（grammar 10–11/12）。"默认本地模型"成立，但**默认 ≠ 可信**。
- **云端默认关思考**买到约 10× 延迟改善（12.8 → 1.27 秒）与 15× 输出 token 缩减，代价只是详尽度（Gloss 4.00 → 2.83、grammar 10/12 → 4/12），**没有把任何一个 4B 栽跟头的错误引回来**。
- **提示词版本哈希的代价**：应用更新 → 每段下次查询各重新生成一次；历史里同一段落会同时存在多个版本的记录。这是**特性**（可比较），不是重复条目。
- **Lookup Key 的成本不对称**：用 SHA-256 而非 64 位哈希，因为碰撞意味着悄悄返回错的解释。
- **敏感判定的覆盖面有限**：只认 `x-kde-passwordManagerHint` = `secret`；不遵守该约定的密码管理器不会被保护；文件与 stdin 输入没有类型标记。
- **面板默认配置下只有 ✕ 一条出路**（自动消失默认关、点外侧在 Wayland 上不可行），因此渲染看门狗不是兜底装饰。
- **退出必须 `g_application_quit()`**；`keyboard_mode=NONE` 意味着 Esc 无效——这两条来自一次真实事故（一个挂了 23 分钟、关不掉的 overlay）。
- **Tauri 画不了 layer 面板**是实测结论，根因未定位；**不要**再从 `GtkApplication` 这条线追根因（假设已被推翻）。`visible(false)` + `init_layer_shell()`、`show_all()`、`gtk-layer-shell` 的 `v0_6` feature 这些知识对任何用 Tauri 的场景仍有效。
- **llama.cpp sidecar 应带 `--api-key` 跑在 loopback**，否则 `#29462`（矛盾下界 OOM）的未认证路径可达。
- **`max_tokens` 与 150 词阈值是一对**：改一个必须看另一个。

### 规格层补的两个决定（票据未覆盖，实现时需优先确认）

1. **CLI 长文本的批次形态**（串行、先报请求数、逐块 stderr 进度、部分失败继续、JSON 多块为数组）——票据 17 只把它推给规格，这里补定。
2. **"复制自动弹"由谁持有监听循环**——票据 07 只定了开关的呈现与默认值。v0 取"开关打开时由 `plainly-desktop` 承担"（`--watch` 或主窗口保持运行），从而默认路径下仍然没有常驻进程；打开这个可选增强才引入一个常驻进程。

### 领域词表的缺口（留给 `/domain-modeling`）

`GLOSSARY.md` 目前没有收 **Provider Profile**（provider + model + thinking 这个组合，Lookup Key 的分量之一）、**Effective Prompt**（出厂默认 + 用户附录的合并结果）、**Level Descriptor**（等级 → 含义的措辞，是提示词数据）这三个本规格反复使用的概念。实现前值得补进词表，避免各人各叫。
