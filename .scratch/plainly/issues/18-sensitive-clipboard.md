# 18 剪贴板里的敏感内容

Labels: wayfinder:issue
Type: grilling
Status: resolved
Blocked by:

## Question

定下**剪贴板里是密码/密钥时怎么办**。

（来自地图 fog："剪贴板里的敏感内容（密码管理器 hint）如何处理"。）

- **判据**：用什么信号判定"这是敏感内容"？
- **判定后做什么**：不发送？不入库？还是只提示？要不要跳过历史？
- **要不要加启发式兜底**（高熵字符串、短串、无空格）？
- **本地 provider 时是否放宽**（内容不出机器）？
- **检查放在哪一层**：core / 面板 / CLI 各查一次，还是 core 一处兜住？
- **局限怎么写**：不遵守该约定的密码管理器不会被保护——这一点要在规格里写明，而不是留白。

## Comments

- **实测（2026-10-05，wl-clipboard 2.3.0 + niri）**：KDE 的密码管理器约定**可观察、可复现**。

  ```
  wl-copy --help          →  --sensitive   Hint that the content is sensitive.
  printf x | wl-copy --sensitive
      wl-paste --list-types      →  ... x-kde-passwordManagerHint
      wl-paste --type x-kde-passwordManagerHint  →  secret
  同一条内容不带 --sensitive 时，该类型的取值为 public
  普通文本始终可读（topsecret）
  ```

  所以判据是**两步、纯本地、不花网络**：**① `x-kde-passwordManagerHint` 出现在类型列表里；② 它的取值是 `secret`。** 二者同时成立即判定为敏感。
  （KeePassXC 等遵守该约定的管理器在复制密码时会做同样的标记；`wl-clipboard` 自己就认得这个类型名。）
- **为什么这件事值得单独一张票**：默认 provider 是**云端**（票据 14），而"复制密码 → 按键 → 内容被发到 api.deepseek.com 并写进本地历史"是一类**用户不会预料到**的泄露。它的代价不对称：误判一次很难挽回，而少解释一段话几乎无损。
- **一条边界**：这不等于"加密历史库"（票据 08 明确不加密）。本票据只处理**入口**：敏感内容压根不进入系统。
- 输入：票据 08（历史与原文入库）、14（默认云端 provider）、07（取词走 data-control，因此**能读到 MIME 类型列表**）、05（CLI 同样经手剪贴板）。

## Answer

四条决策 + 判据实测，2026-10-05 全部按推荐采纳。

### 判据（实测，两步、纯本地、零网络）

```
wl-copy --help          →  --sensitive   Hint that the content is sensitive.
printf x | wl-copy --sensitive
    wl-paste --list-types                      →  ... x-kde-passwordManagerHint
    wl-paste --type x-kde-passwordManagerHint  →  secret
同一条内容不带 --sensitive 时，该类型取值为 public
普通文本始终可读
```

**判据 = ① 类型列表里出现 `x-kde-passwordManagerHint`；② 它的取值是 `secret`。两者同时成立才判定为敏感。**

`wl-clipboard` 自己就认得这个类型名；KeePassXC 等遵守该约定的管理器在复制密码时会做同样的标记。

### 1. 判定后：不发送、不入库、面板明说，且**不给"坚持解释"的出口**

- 代价不对称：**误发一次很难挽回，少解释一段几乎无损**。
- **"不入库"是重点**：否则密码会落进 SQLite 的原文列。注意票据 08 的规则是"**原文必须总是入库**"——**这里是有意的例外，要在规格里点明**，否则实现者会以为 08 的规则是绝对的。

### 2. 启发式兜底：不做（刻意）

- 高熵串 / 短串 / 无空格会同时产生**假阳性**（正常短句被当成密码）与**假阴性**（没打标记的密码照样放过），而最糟的是**给人"有防护"的错觉**。
- 诚实地说"只认这个约定标记"优于虚假安全感。**记为"刻意不做"，而不是漏做。**

### 3. 本地 provider 时不放宽：一条规则，与 provider 无关

- 依赖某个设置的"安全规则"用户没法推理；而"解释一段密码"没有正当需求值得开这个例外。
- **局限必须写进规格**：**不遵守该约定的密码管理器不会被保护。** 留白会让人以为覆盖面比自己以为的更大。

### 4. 检查在 core 一处兜住

- 面板与 CLI 都只**显示结果**，不各自实现。
- 理由：CLI（票据 05）与"复制自动弹"（票据 07）都经手剪贴板；放在界面层就是三处各写一遍，**迟早漏一处**——而漏掉的那一处正好是泄露发生的地方。

### 给下游

- **票据 05**：CLI 同样受这条规则约束（在 core 里兜住），并且需要**一个可区分的结果**——脚本要能分开"provider 失败"与"我们主动拒绝"。
- **票据 06**：面板需要一个**拒绝态**（与票据 17 的"输入过长"共用同一处），且拒绝态也要有出路。
