# 15 配置与密钥的存放

Type: grilling
Status: open

## Question

定下**应用配置放在哪**，以及密钥的边界。

要决定的：

- **Provider 配置**（endpoint、模型 id、thinking 默认）放哪：**配置文件**（可手编、可进 dotfiles、可版本控制）vs **SQLite**（与历史同库）vs 各一半？
- **能力探测的缓存**（"这家支持 `json_schema`"/"上下文 16384"）算不算配置的一部分？它**可重算**，是否该与用户手写的配置分开存放，以免探测结果覆盖人的选择？
- **密钥**：只在 OS keyring（票据 04 已定"不入 SQLite"）。要定边界：
  - keyring 不可用时怎么办——拒绝启动 / 仅会话内存（本次输入）/ 明文文件并明确警告？
  - 多个 provider 的 key 如何命名、如何随 provider 配置一起被引用？
- **应用级设置**（等级、母语、导出格式、UI 语言）与 provider 配置是否同一处？（**票据 09 管提示词的参数化与版本迁移**，别越界；这条只管"这些开关本身存在哪"。）
- 存放位置（XDG config dir？）与是否允许项目级覆盖。

输入：票据 04 的 Answer（预设 + 自定义、能力探测缓存、密钥只在 keyring）、票据 08（历史库）、票据 09（提示词参数化）——三者的边界要在这里划清：**配置**归本票据，**记录**归 08，**提示词**归 09。

## Comments

- 一个已实测的相关事实：`~/.config/plainly/deepseek.key` 这个"一个文件一个密钥、权限 600"的临时做法已经在用（票据 14 的实验），但它**不是**产品方案——它只是让 agent 能拿到 key 跑基准。产品方案在本票据定。
