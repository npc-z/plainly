# 14 第一版系统提示词的标定

Type: grilling
Status: resolved

## Question

把 v0 **出厂的那份系统提示词**定下来，并针对票据 03 实测出的缺陷做出决定。

### 已知缺陷（票据 03，12 段真实难句）

- **`grammar` 0/12**，连 p03 的教科书级倒装（`Not until … did …`）都没触发——模型把它当词条塞进 gloss。怀疑是提示词里 "use null when there is no such obstacle, which is the common case" 过度抑制了它。
- **习语误读**：p02 `bottled it` 被讲成"保守秘密"（正确：临阵怯场），gloss / 改写 / 翻译三处一致地错。
- **语域出错**：p04 `genteel` 释成"礼貌"（应为"有身份的、上流的"）；`repaired to` 整个漏掉；`the Continent` 被降成小写。
- **反讽被拉平**：p08 `to put it mildly` 改成 "in a mild way"（gloss 对、改写与翻译错）。
- **法律语域混淆**：p06 `indemnify` 的释义把"赔偿"与"过错方"混在一起。

### 要决定的

1. **这些缺陷在提示词层面修，还是接受并交给 UI 兜底？** 改措辞、加反例、去掉 null 偏置能修一部分；但本地小模型永远会有这类错，所以"哪些值得修、哪些认了"本身就是决定。
2. **出厂提示词的形态**：票据 03 用的是一段式（把所有规则写在一条系统提示里）。要不要改成**分节式**（显式拆成 blockers → 改写 → gloss → 语法 → 翻译几步）？分节对 4B 是否更好，可以直接测。
3. **要不要写进"不确定就别猜"**（例如允许 gloss 标注不确定），以及 4B 是否真的用得上这条。
4. **与票据 09 的边界**：09 管**参数化与版本迁移**（等级、母语、小节开关、`prompt_version`）；14 只管**这份默认提示词本身写什么**。两者不要互相越界。

### 输入

`.scratch/plainly/bench/`：harness 现成，平均 **1.9 秒/段**，改完提示词重跑全样本不到半分钟。所以这张票据的结论应当**由实测支持，而不是靠感觉**——每改一版就重跑，把通过率与内容缺陷的消退记下来。

（票据 03 的结论已经说明：格式不是问题，内容才是。所以本票据的验收标准不是"契约通过率"，而是那几个具体缺陷是否消退、以及有没有引入新的。）

## Answer

**四条决策（2026-10-05）：出厂提示词 = `v6-synthesis`；`grammar` 字段保留；默认 provider = 云端 + 关闭思考，本地为离线备选；`expression` 子串校验做（定位为本地模式的缓解措施）。**

实测规模：**192 次请求**——本地 6 变体 × 12，DeepSeek 5 变体 × 12（其中 v3 每段重试 3 次）+ 关思考 3 变体 × 12；另加 5 次参数探针。全部对照见 `.scratch/plainly/bench/FINDINGS.md`。

### 1. 出厂提示词：`v6-synthesis`

= v2 的显式 grammar 措辞 + v5 的准确规则（不编造 / 保专有名词 / 反讽） + "必须是真改写，不得原样返回"。

**诚实附注**：12 段样本上 v2/v5/v6 **统计上分不开**（思考开：grammar 11/10/10、gloss 3.50/3.75/4.00；思考关：4/3/4、2.75/2.75/2.83）。选 v6 的理由**不是名次**，而是它的每个组成部分**各自被独立证据支持**且彼此不冲突：

- **grammar 措辞**：云端触发 8/12 → 11/12（本地始终 0/12，够不着）
- **不编造**：p09 凭空多出的 "the missing part" 消失
- **保专有名词**：`the Continent` 的大写与"欧洲大陆"含义回来
- **反讽规则**：`to put it mildly` 的 gloss 回来
- **"必须是真改写"**：针对 v3 翻车模式的保险

**v3（分步式）剔除**——它在两条路径上都崩，方式不同：有 schema 强制时**内容崩**（本地 5/12 的 "comprehensible" 就是原句照抄），无强制时**结构崩**（DeepSeek 把字段名改成 `paraphrase`，12/12 违约）。

### 2. `grammar` 字段保留（不再是悬案）

| | 本地 4B | 云端思考开 | 云端思考关 |
|---|---|---|---|
| grammar 触发 | 0–1/12 | 10–11/12 | 3–4/12 |

字段是活的，而且注释质量高（分词从句、法律 `indemnify X against Y` 的框架、插入语断句、倒装）。**本地 4B 够不着结构解释这条路**；渲染器 "null → 省略该节"（票据 01 已定）正好兜住。

### 3. 默认 provider：云端 + 默认关闭思考；本地为离线备选

`{"thinking":{"type":"disabled"}}` 买到 **10× 延迟**（12.8 → 1.27 秒）与 **15× 输出 token**（2610 → 178），代价只是**详尽度**（gloss 4.00 → 2.83、grammar 10/12 → 4/12），**没有把任何一个 4B 栽跟头的错误引回来**。

- **云端（思考关）**：1.3 秒、~175 token、习语与语域正确 → **默认**
- **本地**：1.7 秒、离线、**契约强制**（schema 约束解码）、但**在习语和语域上自信地错**（`bottled it` 在 6 个变体里全错）→ 备选，且 **UI 必须给"与原文核对"的位置**
- **云端（思考开）**：10–13 秒、15× token、4.0 gloss、10–11/12 grammar → 详尽档，不是默认

### 4. 贯穿全部数据的一条

**本地那些错是能力问题，不是提示词问题。** 每个缺陷在本地六个变体里全部存活，而云端在**同一批提示词**下全部做对。这同时解释了为什么 Q1 的抉择对本地几乎无影响——提示词工程碰不到 4B 的天花板。

### 5. 给下游的三条（已分别记入票据 04 与 06）

- **重试只救随机畸形，救不了系统性漂移**：v3 的错字段名在 DeepSeek 上 3/3 复现，白跑 24 次调用。
- **推理模型的 token 预算**：思考态下 `reasoning_tokens` 可占 completion 的 90%+，`max_tokens` 必须按思考预算给，否则长句被截断成畸形输出。
- **思考开关的三个坑**：规范写法 `{"thinking":{"type":"disabled"}}`；`{"thinking":false}` 是 422；`{"enable_thinking":false}` **静默无效**。另外思考态下 `temperature`/`presence_penalty`/`frequency_penalty` **全部静默失效**。

### 6. 资产

`.scratch/plainly/bench/`：`FINDINGS.md`（本地 vs 云端全对照 + 思考开关实测）、`prompts/`（v1–v6）、`schema.json`、`passages.json`、`bench.py`（双 provider + 重试 + 思考开关，仅 stdlib）、`results/`（全部原始输出）。

**本票据不做**：不写实现。**提示词文本归这里；参数化、存储、版本化与迁移归票据 09。**

## Comments

- **⚠️ 2026-10-05 票据 09 结清后回填：出厂提示词要从 v6 升到 v7。** 要求是**内联等级描述表**——即 `{{LEVEL}}` 不能只代入标签，要代入"标签 + 含义"（如 `A2 (very common words, short sentences, concrete)`）。
  理由不是措辞偏好，而是**实测**：只发标签时，**3/8 个相邻等级对产出了逐字相同**的解释（p04/p06/p12 上两个等级完全相同）；把原技能里本来就有、却没进提示词的那张等级表内联之后，降到 **1/8**，A2 的平均词长 4.29→**4.05**、与原文相似度 0.460→**0.395**（改写更彻底）。
  另外实测发现**契约内部有一处互相拉扯**：C1 的描述"keep most of the original structure"与本票据保留的那条"it must be a real restatement: never return the passage unchanged"冲突——而后者赢，这很可能就是 **B2 与 C1 无法区分**（4.32 vs 4.29）的原因。v7 的 C1 描述要在**不与"必须真改写"冲突**的前提下表达"保留更多原结构"。
  数据：`bench/FINDINGS.md` 的 "The two parameters have very different teeth" 一节；原始输出 `bench/results/deepseek/v6-synthesis-{level,desc}*.json`。
