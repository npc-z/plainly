# 16 主窗口（历史、搜索、设置）的信息架构

Type: prototype

## Question

定下 `plainly-desktop`（Tauri 主窗口）的信息架构。**面板已由票据 06 结清**，这里只做主窗口——即用户按 ⤢ 之后进入的那个世界。

- **导航结构**：历史与设置是**两个屏幕**（侧栏或标签切换）还是**一个可滚动的页**？窗口是单窗口还是允许开多个？
- **历史**：列表与详情怎么切分（左右分栏 / 列表进详情 / 详情浮层）？**搜索框的位置**（票据 08 已定 FTS5 **只索引英文**）？**标签怎么呈现**（08：v0 只做手动）？**删除与全量清除放哪**（08：硬删 + 全量清除二次确认）？
- **导出的入口**：三条导出（Markdown / Anki CSV / 原始 CSV）放**单条详情里**还是**全局**？08 定了形态，**没定位置**。
- **设置屏幕分几节**（等级与母语 / provider 与模型 / 提示词 / 外观…）？其中已有三条外部约束：票据 07 要求"复制自动弹"在能力不足时**灰掉 + 一行可操作说明**（不是隐藏）；票据 06 定了思考开关**只在设置里、默认关**；票据 15 定了配置分段 `[app]` / `[providers.*]` / `[prompts]`。
- **首次运行引导**（没有 key、没有可用 provider）：是设置页的一个状态，还是一个独立的引导流？**（来自地图 fog）**
- **搜索与标签的具体形态**。**（来自地图 fog；票据 08 已给出判据：FTS5 只索引英文、tokenizer per-table、标签只手动）**

## Comments

- **与票据 06 的边界**：06 定的是**面板**（形态、状态、退出路径、provenance、重新生成、activate 语义、UI 语言）。本票据**不重新讨论**那些；只定主窗口。UI 语言（中文为主 + 文案集中）已由 06 定，这里沿用。
- **可复用的原料**：票据 06 的原型 `.scratch/plainly/ui/panel-ia.html` 里的**假文档背景**与**面板本体**可以继续用——主窗口的原型最好把面板也画进去，让"两种表面之间的关系"（面板是临时的、窗口是常驻的）在原型里就看得出来。
- **一条来自 06 的教训**：`plainly-desktop` 是 Tauri 窗口，**不是** layer-shell 表面；票据 12 的结论只否定"用 Tauri 画 layer 面板"，**不影响 Tauri 画普通窗口**。不要因为 12 就对主窗口的渲染路径产生怀疑。
- **来自票据 09 的三条 UI 要求**：
  1. 设置页显示等级时**必须带它的含义**（实测：只发等级标签时，3/8 相邻等级对产出逐字相同的解释）。**描述表的措辞归 09 的提示词数据**，16 只负责把它显示出来。
  2. **提示词附录的编辑器**（写入 `[prompts]`）。要在界面上说清"**只能加、不能删**基础规则"以及为什么——基础保持 artifact 的定义，否则各人的历史就不再可比。
  3. 历史要能**按 prompt 版本区分**同一段落的多条记录：提示词一改（包括应用更新带来的出厂提示词变化），哈希就变，于是同一段落会出现**新的一行**。这是**特性**（可以比较新旧提示词的效果），但界面上要看得出来，否则会被当成重复条目。
- **来自票据 06 的设置项（2026-10-05 补充）**：设置屏幕必须包含**面板自动消失**的**两个**控件——**开关（默认关）**与**时长（默认 20 秒，仅在开关打开时可用）**。两者**独立**；**时长不要用 `0` 表示"永不"**（"关"已经有开关，两种表达迟早矛盾）。**时长控件取什么形态**（数字输入 + 合理范围，还是预设档位）归本票据。两个键都落在 `[app]` 段（票据 15：人的选择走配置，可重算的才走探测缓存）。

输入：`GLOSSARY.md`；票据 [06](06-desktop-ui-ia.md)（面板）、[08](08-history-schema-export.md)（schema 与导出）、[15](15-config-and-secrets-store.md)（配置分段）、[07](07-linux-trigger-integration.md)（能力探测的呈现要求）。

## Answer

2026-10-05，六条决策全部按推荐采纳。原型：`.scratch/plainly/ui/main-window-ia.html`（三个结构性不同的变体 + screen / provider / panel 三个**只为观察而存在**的轴）。

### 1. 导航结构：A 的骨架 + 借 C 的日期分组

- **顶部标签（历史 / 设置）+ 列表常驻（左约 330px，含搜索框）+ 详情在右**；列表按日期分组（今天 / 昨天 / 更早）。
- **为什么不是 B（单栏推进）**：桌面窗口 1000px 以上时，单栏**把一半宽度浪费掉了**，而且"看一条 → 返回 → 看下一条"每次多一次点击。
- **为什么不是 C（时间线 + 浮层设置）**：时间线在"我昨天看的那句"这类回忆式检索上更强，但**列表常驻 + 搜索框**已经覆盖主要检索方式；而分栏天然容纳**同一段落的多个 prompt 版本并排比较**（票据 09 的要求）。把日期分组借进 A 就拿到了 C 的主要长处。

### 2. 搜索与标签

- 搜索框**固定在列表顶部**；**只搜英文字段**（票据 08：FTS5 只索引英文），并在搜索框下**用一行小字说明"中文翻译暂不可搜"**——08 要求把这条限制写成事实而不是隐藏缺陷，**界面就是它该出现的地方**。
- 标签：**在详情里编辑**；列表中显示为**可点击的筛选 chip**。
- **列表行必须显示 prompt 版本**（连同 provider 模型、等级、标签、时间）。票据 09 说同一段落会有多版本的记录且**这是特性**——不显示版本，用户就会把它当成重复条目。

### 3. 导出入口：两处分工

- **详情里**：复制 markdown / 导出这一条。
- **设置的数据节**：三条全局导出（Markdown / Anki CSV / 原始 CSV）。
- 理由：单条导出是"我正在看这条"的动作，全局导出是"我要搬走全部"的动作；混在一起会让每条记录都挂三个导出按钮。

### 4. 设置分五节

**语言与等级 / Provider / 提示词 / 行为 / 数据**——与票据 15 的配置分段（`[app]` / `[providers.*]` / `[prompts]`）对齐。**"数据"这节有实际内容**：三条导出、打开数据目录、清除全部历史。
其中不少内容**已被别的票据定死，本票据只负责放置**：等级必须带含义显示（09）、"复制自动弹"能力不足时灰掉 + 说明（07）、思考开关只在设置里（06）、提示词附录"只能加不能删"的解释（09）、**面板位置**与**面板自动消失**（06 及其修正）。

### 5. 首次运行 = 设置页的一个空状态

- **没有可用 provider 时，窗口直接开在设置屏的这一状态**：两条路（填 key / 探测本机）本来就是设置页的两个控件。
- **不做独立引导流**：只有一条代码路径，而且用户以后随时能回到这一屏。独立引导流是一段额外要维护的状态机。

### 6. 面板位置：可配置（四个角 + 跟随当前显示器）

- 位置是 `[app]` 的两个键（角 / 输出）。**角是分辨率无关的**——换分辨率或换显示器不会把面板丢到屏幕外，这正是它优于自由坐标的地方。
- **不做自由鼠标拖动**。成本**不在代码量**（约 50–100 行，且不涉及新协议：按住按键期间的运动事件会送给收到按下的表面），而在**四个配套问题**：① 拖动与按钮的交互仲裁；② 位置存什么才能在换分辨率/缩放/显示器后仍然合理；③ **多显示器要换输出并用该输出的坐标系重新锚定**（自由拖动里最麻烦的一块）；④ 必须配套"位置复位"。**角设置用约 10% 的成本拿到约 90% 的收益**，而且位置永远可预测——对"按键看一眼、眼睛不用找"来说，可预测性本身值钱。

### 对票据 06 的修正（本票据顺带发现）

原型的"面板与主窗口同屏"那一屏暴露了一个真实冲突，而追究它时发现**票据 06 原 Answer 里有一句机制说错了**：它写"点外侧关闭"是"唯一的指针出路"，但**在 Wayland 上 layer 表面只能看到落在自己输入区域内的点击**——点在别的窗口上的点击客户端收不到（Wayland 的隔离模型，不是合成器的限制）。已回填给票据 06（连同由此逼出的渲染看门狗）与票据 07。
