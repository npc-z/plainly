# 06 桌面 UI 信息架构

Type: prototype
Status: resolved

## Question

用**粗糙原型**定下界面结构与主流程，判断"v0 有哪几个屏"。

- **面板**：结果怎么呈现（分节折叠？等级标识？流式时逐段出现？）、复制/导出按钮、语法小节的位置。
- **历史**：列表、全文搜索、标签、导出入口。
- **设置**：等级（A1–C1+）、母语、provider 与 key、输出小节开关、自定义系统提示。
- 切换与返回：面板是常驻还是按需弹出；历史是独立窗口还是面板展开。

产出：低保真线框或可点的粗糙原型 + 一张"v0 屏幕清单"（含明确不做的屏）。

## Comments

- **从雾区毕业进来的问题**：**流式呈现**——JSON 还在流、`comprehensible` 先到而 `glosses` 未到时，面板显示什么？先显示已完成的节，还是等产物齐了整体呈现？（本地 CPU 推理一次 30–60 秒，这段等待必须有交代。）
- 前提已由 [01 输出契约 schema 与 markdown 渲染](01-output-contract.md) 定下：四件套字段 + 逐字复刻的五节，且 `grammar` 可空（空则整节省略）。所以待定的只是**呈现策略**，不再是"渲染什么"。
- **来自票据 14 的一条硬要求**：**本地模型的输出不可呈现为权威。** 实测里它在习语和语域上**自信地错**（`bottled it` 讲成"保守秘密"，6 个提示词变体全错；`genteel` 讲成"礼貌"，5/5），而同一批提示词云端全对——**这是能力边界，不会因为改提示词而消失**。因此当 provider 是本地时：
  - 原文必须与解释**并排可见**（学习者要能自己核对）；
  - gloss 不给"记住这个"这类权威措辞，除非旁边就有核对入口；
  - 考虑让面板**标出是哪个 provider 生成的**，以及给的 gloss 数量差异（本地 ~1.7 个/段 vs 云端 ~2.8）。
  云端（默认）不需要这层保护，但两者共用同一个面板——所以这层保护应当**按 provider 开关**，而不是全局降低可信度表达。
- **来自票据 08 的两条 UI 要求**（由幂等键缓存逼出）：
  - **显示 provenance**：这条解释是**哪个 provider / 模型**出的（缓存命中的可能是本地 4B 的旧答案）。
  - **"重新生成"入口**：绕开缓存重跑。最现实的场景就是"本地模型把习语讲错了 → 一键换云端重生成"——票据 14 证明这个场景一定会发生。**有缓存就必然需要这个出口。**
- **来自票据 05 的一条状态要求**：面板有两条被唤起的路径——**用户主动打开**，以及**运行中的实例收到第二个进程的 argv**（`tauri-plugin-single-instance` 的 D-Bus 回调，键绑走的就是这条）。后者要有一个明确状态，因为它在**用户没在看应用**的时候把面板推出来：此时该抢焦点吗？该显示加载态吗（冷启动首次会有延迟）？该在多久无操作后自动消失？这三条都归本票据。
- **⚠️ 2026-10-05 更正（票据 07）**：上一条的前提**作废**——Tauri 不参与画面板（票据 12），面板是**独立进程**，由**合成器键绑直接 spawn**，因此没有"运行中实例收到 argv"这条路径。但那三个问题**依然存在，而且更强**：面板每次都是**新起的进程**，所以 ① 首次要冷启动（GTK 约百毫秒 + provider 1.3–1.7 秒），加载态必须设计；② 它锚定且 `keyboard_mode=NONE`，**不该抢焦点**；③ 无操作后自动消失的时长要定。
  **另有一条新问题**：`GtkApplication` 的 `activate` 复用已有窗口（票据 07 实测：连按两次只出一个面板），所以**第二次按键发生在面板已显示时**，UI 要决定那意味着什么——重新读剪贴板并刷新？只是把面板再显示一次？还是忽略？
- **⚠️ 面板的"退出路径"必须显式设计**（来自票据 07 的一次真实事故）：面板 `keyboard_mode=NONE`，**不接收键盘事件，所以 Esc 无效**。它只有两条出路——**定时自动消失**与**指针操作**（点面板外／点关闭区）。而 `GtkApplication` 退出必须用 `g_application_quit()`，`gtk_main_quit()` 管不了它的主循环（我的探针程序就这么在桌面上留了一个挂 23 分钟、盖在最上层且关不掉的面板）。
  所以本票据要定的是三件：**多久自动消失**、**点外侧是否关闭**、**是否有显式关闭按钮**。这三条不是装饰——它们是用户唯一的出路。

- **原型（2026-10-05）**：`.scratch/plainly/ui/panel-ia.html` —— 三个**结构性不同**的面板变体：**A 精简条**（原文常显 → 改写 → gloss → 翻译，页脚只有 provenance + 两个图标）、**B 标题栏+分节**（标题栏含 provenance 与四个动作，分节可折叠，页脚有倒计时）、**C 渐进出卡**（改写为英雄区，gloss 逐张点开，**翻译与原文都默认隐藏**）。浮动控制条切换（也支持 `?variant=`），另有两个**只为了看状态而存在**的轴：state（加载/结果/出错）与 provider（云/本地）。
  一行计划写在文件顶层注释里。已用 `firefox --headless --screenshot` 渲染验证（`var-*.png`、`b-strip.png` 是渲染产物，不入库——与 02 的"截图不保留"一致）。
  **C 的价值在于它把一条已定要求的代价摆出来**：原文要两次点击才可见，而票据 14/08 要求本地输出必须能与原文核对。

## Answer

2026-10-05，五条决策全部按推荐采纳。原型：`.scratch/plainly/ui/panel-ia.html`（三个结构性不同的变体 + state / provider 两个**只为看状态而存在**的轴）。

### 面板形态：B 的骨架 + A 的正文密度

- **固定标题栏**：标题、**provenance chip**（云 `deepseek-flash`；本地 `Qwen3-4B · local`，琥珀色）、四个动作——复制 / **⟳ 重新生成** / ⤢ 打开历史 / ✕ 关闭。
- **正文（取 A 的密度）**：原文**常显**（暗色斜体、小一号）→ 改写 → gloss 紧凑列表（`expression → gloss`，顺序从最挡路的开始）→ 翻译（绿色）。
- **分节可折叠（取 B）**：原文 / 改写 / 关键帮助 / 语法 / 翻译各有小标题；`grammar` 为 null 时该节显示"本段不需要"，而不是消失（用户要能区分"没有"与"没生成"）。
- **本地 provider 时正文下方固定一条核对提示**：「本地模型；它的习语解释可能自信地错——请对照上方原文，或 ⟳ 换成云端重新生成」。这把票据 14 的结论与票据 08 的"原文必须可与解释核对"**落到界面上的固定位置**，而不是指望用户自觉。
- **为什么不用 C**：C 的渐进出卡把**原文与翻译都默认藏起来**，与"本地输出必须能与原文核对"直接冲突。C 留在原型里作为**那条要求的代价证明**，不折进规格。

### 状态

- **加载**：原文已经可见（用户看得到正在解释哪一段）+ 骨架条 + `explaining…`。**首次冷启动 1.3–2 秒**（票据 07），所以加载态不是可选项。
- **出错**：**单一错误态**——人类可读原因 + 已重试情况 + **"剪贴板内容未变、什么都没存"**。每类失败的具体**文案**属于规格层面（分类与重试策略已在票据 04/10 定），不是本票据要定的决策。
- **任何状态都有出路**（见下）。

### 三条退出路径

- **自动消失：默认关**；打开后默认 20 秒。开关与时长**都可配置**（用户补充 2026-10-05；默认值由用户定为**关**）。
  - **默认关的直接后果**：面板会**一直留在左上角**，直到用鼠标点掉（点外侧或 ✕）。而 `keyboard_mode=NONE` 意味着 **Esc 无效**——所以**指针是默认路径下唯一的出路**，这两条不是锦上添花。
  - **代价（诚实记下）**：面板宽 470px 且不抢焦点，因此它**不打断你打字，但会遮挡**左上角内容。
  - **好处**：它天然契合"复制 → 按键 → 复制 → 按键"的工作流——下一次按键会把面板**原地换成**新的解释（`activate` 复用语义），所以键盘用户全程不必碰鼠标。
  - 打开自动消失时才显示倒计时与"点外侧关闭"提示。
- **点外侧关闭：是**——它是**唯一的指针出路**，不是装饰。
- **显式 ✕：保留**。
- **加载与出错态同样有出路。** 这条是被一次真实事故逼出来的：面板 `keyboard_mode=NONE`、**按 Esc 无效**，我自己留过一个挂了 23 分钟、关不掉的浮层。退出必须走 `g_application_quit()`（票据 07 已记该陷阱）。
- **开关与时长必须是两个独立配置项**：不要用"时长 `0` = 永不消失"来表达关闭——那样"关闭"就有开关和魔法值两种写法，迟早互相矛盾。**自动消失关掉时，"任何状态都有出路"依然成立**（点外侧 + ✕ 仍在），这是把它做成可选项的前提。
- 两个配置项归 `[app]` 段（它们是**人的选择**，不是可重算的探测缓存——票据 15 的边界）。设置页的控件形态归票据 [16](16-main-window-ia.md)。

### `activate` 复用语义：重新读剪贴板并刷新

按第二次键的人**几乎总是复制了新的一段**；真是同一段时幂等键（票据 08）会命中缓存，成本近零。只重置倒计时会让用户以为程序没反应。

### 思考开关：只在设置里，默认关

依据票据 14 的实测（开 9.8–12.8 秒 / 关 1.3 秒）。**10 秒在"按键看一眼"里不可用**；而面板是最稀缺的表面，不该为它加控件——真想要详尽的人已经有 ⟳ 这个入口。存储归票据 15 的 `[providers.*]`。

### UI 语言：中文为主 + 文案集中

v0 是中文母语者的自用工具 → 写中文。但**界面文案集中成一份可替换资源**（一个 `strings` 模块），**不引入 i18n 框架**——这是"将来能翻译"与"将来必须重写"的区别，而成本近零。markdown 内容仍为固定英文（票据 01 已把内容与 UI 标题拆开）。

### ⚠️ 本票据的范围（重要）

票据原文的 Question 含「主窗口的导航结构（历史/设置）」，而**本轮原型与决策只覆盖面板**。为不带着未答的问题关票，**主窗口那一半拆成 [16 主窗口的信息架构](16-main-window-ia.md)**，本票据就面板部分结清。
这样切是因为：面板是产品里最有争议的表面（多条已定要求在此汇聚），而主窗口是常规的列表/详情/设置结构——两者各值得一个原型。

### 资产

原型留在 `.scratch/plainly/ui/panel-ia.html`。**没有**像票据 02 那样放进孤立分支，理由：它的用途就是**用户打开来看**，多一步"先取出来"会直接挡住这张票的目的；而仓库尚无应用代码，`.scratch/` 本身就是工作区，不存在"污染 main"的问题。**变体全部保留**（A/C 是决策的代价证明）。渲染产物 `var-*.png` / `b-strip.png` **不入库**，与票据 02 的"截图不保留"一致。
- **来自票据 07 的一条呈现要求**：设置页里的**"复制自动弹"开关**，在桌面不具备 data-control 能力时要**灰掉并附一行可操作的说明**（例如"需要 wlroots 类合成器的 data-control 协议"），**不要隐藏**——隐藏会让用户以为这功能不存在，灰掉加说明等于把能力矩阵教给用户。
- **来自票据 17 与 18 的两个新状态（2026-10-05）**：
  1. **多块堆叠**：输入被切成多块时，面板**按原文顺序把各块堆叠在一个可滚动面板里**（票据 17）。不要做分页——键盘模式 NONE，翻页只能靠指针，而堆叠没有隐藏状态。
  2. **两种拒绝态**：**内容被标记为敏感**（票据 18）与**输入过长**（票据 17，>5 块）。两者都要**明说原因**（"这段有敏感标记，未发送也未保存" / "这段太长，请用 CLI 或先拆分"），并且**拒绝态同样要有出路**——面板不抢焦点，用户很可能正在别处打字，一个关不掉的拒绝浮层比没有拒绝更糟（参见票据 07 记录的那次真实事故）。
- **从雾区移进来的问题**：**思考开关是否作为用户可见的设置？** 票据 04 已在 provider 层把它建模为 `thinking: on | off | unsupported`（默认 off），并明确"UI 是否暴露留给本票据"。要定的是：设置页里出现"详尽档 / 快速档"这样的开关，还是写死关闭、只在诊断信息里可见？实测依据：开思考 = 10–13 秒、4.0 gloss、10–11/12 grammar；关思考 = 1.3 秒、2.8 gloss、3–4/12 grammar——**正确性不变，详尽量变**，所以这是一个真实的用户偏好而非技术必要。
