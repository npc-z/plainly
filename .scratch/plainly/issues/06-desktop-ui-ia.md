# 06 桌面 UI 信息架构

Type: prototype
Status: open

## Question

用**粗糙原型**定下界面结构与主流程，判断"v0 有哪几个屏"。

- **面板**：结果怎么呈现（分节折叠？等级标识？流式时逐段出现？）、复制/导出按钮、语法小节的位置。
- **历史**：列表、全文搜索、标签、导出入口。
- **设置**：等级（A1–C1+）、母语、provider 与 key、输出小节开关、自定义系统提示。
- 切换与返回：面板是常驻还是按需弹出；历史是独立窗口还是面板展开。

产出：低保真线框或可点的粗糙原型 + 一张"v0 屏幕清单"（含明确不做的屏）。

## Comments

- **从雾区毕业进来的问题**：**流式呈现**——JSON 还在流、`comprehensible` 先到而 `glosses` 未到时，面板显示什么？先显示已完成的节，还是等产物齐了整体呈现？（本地 CPU 推理一次 30–60 秒，这段等待必须有交代。）
- 前提已由 [01 输出契约 schema 与 markdown 渲染](01-output-contract.md) 定下：四件套字段 + 逐字复刻的五节，且 `grammar` 可空（空则整节省略）。所以待定的只是**呈现策略**，不再是"渲染什么"。
