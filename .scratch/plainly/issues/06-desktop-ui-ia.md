# 06 桌面 UI 信息架构

Type: prototype
Status: open

## Question

用**粗糙原型**定下界面结构与主流程，判断"v0 有哪几个屏"。

- **面板**：结果怎么呈现（分节折叠？等级标识？流式时逐段出现？）、复制/导出按钮、语法小节的位置。
- **历史**：列表、全文搜索、标签、导出入口。
- **设置**：等级（A1–C1+）、母语、provider 与 key、输出小节开关、自定义系统提示。
- 切换与返回：面板是常驻还是按需弹出；历史是独立窗口还是面板展开。

产出：低保真线框或可点的粗糙原型 + 一张"v0 屏幕清单"（含明确不做的屏）。

## Comments

- **从雾区毕业进来的问题**：**流式呈现**——JSON 还在流、`comprehensible` 先到而 `glosses` 未到时，面板显示什么？先显示已完成的节，还是等产物齐了整体呈现？（本地 CPU 推理一次 30–60 秒，这段等待必须有交代。）
- 前提已由 [01 输出契约 schema 与 markdown 渲染](01-output-contract.md) 定下：四件套字段 + 逐字复刻的五节，且 `grammar` 可空（空则整节省略）。所以待定的只是**呈现策略**，不再是"渲染什么"。
- **来自票据 14 的一条硬要求**：**本地模型的输出不可呈现为权威。** 实测里它在习语和语域上**自信地错**（`bottled it` 讲成"保守秘密"，6 个提示词变体全错；`genteel` 讲成"礼貌"，5/5），而同一批提示词云端全对——**这是能力边界，不会因为改提示词而消失**。因此当 provider 是本地时：
  - 原文必须与解释**并排可见**（学习者要能自己核对）；
  - gloss 不给"记住这个"这类权威措辞，除非旁边就有核对入口；
  - 考虑让面板**标出是哪个 provider 生成的**，以及给的 gloss 数量差异（本地 ~1.7 个/段 vs 云端 ~2.8）。
  云端（默认）不需要这层保护，但两者共用同一个面板——所以这层保护应当**按 provider 开关**，而不是全局降低可信度表达。
- **来自票据 08 的两条 UI 要求**（由幂等键缓存逼出）：
  - **显示 provenance**：这条解释是**哪个 provider / 模型**出的（缓存命中的可能是本地 4B 的旧答案）。
  - **"重新生成"入口**：绕开缓存重跑。最现实的场景就是"本地模型把习语讲错了 → 一键换云端重生成"——票据 14 证明这个场景一定会发生。**有缓存就必然需要这个出口。**
- **来自票据 05 的一条状态要求**：面板有两条被唤起的路径——**用户主动打开**，以及**运行中的实例收到第二个进程的 argv**（`tauri-plugin-single-instance` 的 D-Bus 回调，键绑走的就是这条）。后者要有一个明确状态，因为它在**用户没在看应用**的时候把面板推出来：此时该抢焦点吗？该显示加载态吗（冷启动首次会有延迟）？该在多久无操作后自动消失？这三条都归本票据。
- **⚠️ 2026-10-05 更正（票据 07）**：上一条的前提**作废**——Tauri 不参与画面板（票据 12），面板是**独立进程**，由**合成器键绑直接 spawn**，因此没有"运行中实例收到 argv"这条路径。但那三个问题**依然存在，而且更强**：面板每次都是**新起的进程**，所以 ① 首次要冷启动（GTK 约百毫秒 + provider 1.3–1.7 秒），加载态必须设计；② 它锚定且 `keyboard_mode=NONE`，**不该抢焦点**；③ 无操作后自动消失的时长要定。
  **另有一条新问题**：`GtkApplication` 的 `activate` 复用已有窗口（票据 07 实测：连按两次只出一个面板），所以**第二次按键发生在面板已显示时**，UI 要决定那意味着什么——重新读剪贴板并刷新？只是把面板再显示一次？还是忽略？
- **⚠️ 面板的"退出路径"必须显式设计**（来自票据 07 的一次真实事故）：面板 `keyboard_mode=NONE`，**不接收键盘事件，所以 Esc 无效**。它只有两条出路——**定时自动消失**与**指针操作**（点面板外／点关闭区）。而 `GtkApplication` 退出必须用 `g_application_quit()`，`gtk_main_quit()` 管不了它的主循环（我的探针程序就这么在桌面上留了一个挂 23 分钟、盖在最上层且关不掉的面板）。
  所以本票据要定的是三件：**多久自动消失**、**点外侧是否关闭**、**是否有显式关闭按钮**。这三条不是装饰——它们是用户唯一的出路。
- **来自票据 07 的一条呈现要求**：设置页里的**"复制自动弹"开关**，在桌面不具备 data-control 能力时要**灰掉并附一行可操作的说明**（例如"需要 wlroots 类合成器的 data-control 协议"），**不要隐藏**——隐藏会让用户以为这功能不存在，灰掉加说明等于把能力矩阵教给用户。
- **从雾区移进来的问题**：**思考开关是否作为用户可见的设置？** 票据 04 已在 provider 层把它建模为 `thinking: on | off | unsupported`（默认 off），并明确"UI 是否暴露留给本票据"。要定的是：设置页里出现"详尽档 / 快速档"这样的开关，还是写死关闭、只在诊断信息里可见？实测依据：开思考 = 10–13 秒、4.0 gloss、10–11/12 grammar；关思考 = 1.3 秒、2.8 gloss、3–4/12 grammar——**正确性不变，详尽量变**，所以这是一个真实的用户偏好而非技术必要。
