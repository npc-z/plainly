## 落地形态

**`plainly-desktop` 现在是 lib + bin**：bin 只有参数解析和 `window::run`，其余全在 lib 里，因为一条
seam 就够了——`Desktop`（`src/app.rs`）是窗口自己的状态与动作，Tauri 命令（`src/commands.rs`）只是它的
翻译层。测试驱动的是 `Desktop` 的公共 API（`tests/window.rs`），也就是**前端看到的那份数据**：
哪个查询命中哪些行、详情里五节长什么样、导出落在哪、首次运行该开在哪个屏。

| 文件 | 它是什么 |
| --- | --- |
| `src/app.rs` | 窗口状态与动作：store / 配置文件 / secrets 三把锁，搜索、标签、删除、导出、设置 |
| `src/view.rs` | 一行、一条详情的形状（含 `prompt_version`、`local`、`last_seen` 秒） |
| `src/settings.rs` | 五节的形状：等级含义、provider 列表、key 状态、小时长范围、能力可用性 |
| `src/strings.rs` | 界面文案，一次交给前端；前端自己不留一句中文 |
| `src/commands.rs` + `src/window.rs` + `src/main.rs` | Tauri 命令表、进程、单实例交接 |
| `src/capability.rs` / `src/clipboard.rs` | 与面板同源的合成器探测；写剪贴板走 `wl-copy`，退到 `xclip` |
| `ui/index.html` / `ui/style.css` / `ui/app.js` | 前端：无框架无打包器，`tauri-build` 直接嵌进二进制 |

**`tauri-plugin-single-instance` 换成了自己的实现**（`src/single.rs`）：这台机器没有到 crates.io 的路，
插件不在本地 registry 里。它做的交接很小：`$XDG_RUNTIME_DIR` 下一个 `flock` 决定谁是窗口（锁随进程
消失，所以没有陈旧状态），第二个启动在那个窗口的 socket 上说一句 `activate`。**不用「socket 文件本身就是
锁」那种写法**：被 `SIGKILL` 的窗口留下的 socket 无法再次 `bind`（内核按 inode 判 `EADDRINUSE`），必须先
删再绑，而两个启动同时删+绑就会都变成窗口——这正是这个模块要防的事。
规格里对插件提的那条注意（**别开 `semver` feature**，否则升级后新旧实例互不接管）在这里是不存在的东西：
名字无条件，所以旧窗口和新二进制仍然认可同一个窗口。

**导出没有文件对话框**：三条全局导出与「导出这一条」都写到数据目录，文件名带时刻（`plainly-history-…`），
界面把落点念出来。v0 的取舍是「一个总能念回来的路径」胜过「一个选择器」。

## 给下游的交接

- **复制自动弹的监听没有实现，而且 v0 没有任何东西会去拉起它**。开关、能力探测、灰掉 + 说明、
  `--watch` 参数与「开关不生效」那句提示都在；监听循环本身不在。规格 §12 的补定说得很清楚：开关打开时
  由 `plainly-desktop` 承担监听（`plainly-desktop --watch`）。**这个常驻进程要由监听票据负责拥有**——
  由键绑或桌面自启动在开关打开时拉起、关闭时停掉；本窗口不会在写出 `copy_auto_popup = true` 时自己
  spawn 一个进程，那会绕过「默认路径下没有东西需要常驻」这条承诺，也会让窗口在用户没要求的时候变成
  一个父进程。
- **窗口自己的决定有自动化测试，渲染与退出路径没有**：`Desktop` 的公共 API 就是前端看到的那份数据，
  由 `tests/window.rs` 驱动（规格 §13 排除的是**渲染**——webview、合成器、看门狗、退出路径——不是这些
  决定）。真机清单见 `docs/desktop-manual-checks.md`。
- `ui/` 是静态资源，没有构建步骤；改前端不需要 node，也不需要重新 `pnpm install`。

## 已知取舍

- **详情里的「原文」用等宽预排的斜体块，不做 markdown 渲染**：面板与窗口都只显示纯文本，一份渲染器
  （`plainly_core::render`）负责 markdown 导出，界面不做第二份。
- **`confirm()` 用的是 WebKit 自带的对话框**：`window.confirm` 在 WebView 里可用，省掉一个 Tauri
  对话框插件；代价是它长得不像应用自己的界面。删除与全量清除两处二次确认走它。
- **设置改动即时落盘**：每个控件 `change` 就写一次配置文件，顶栏闪一句「已保存」。没有「保存」按钮，
  因为一个忘了按的保存按钮会和「我以为已经改了」这件事一起出现。
- **列表按本地日分组在前端做**：后端只给 `last_seen` 的秒数，因为只有 webview 知道这台机器的时区
  （`record_fts` 的日期在导出里仍是 UTC 日期，两者只在本机偏移跨零点的那几条上不同）。
- **`is_local` 由 provider 名解析出的 endpoint 决定**，不是名字表：`ollama` 指向别的机器就不是本地，
  自定名指向 `127.0.0.1` 就是。解不出来的名字**不**当作本地——不能凭猜测把「本地模型可能自信地错」
  那句话放到不该放的地方。
- **`wl-copy` 是运行时依赖，不是 crate 依赖**：它在 devShell 里。两个都起不来时复制会说失败，而不是
  假装成功。
- **`capability.rs` 与面板的那份是重复的**（同一段 registry 列举，约 25 行）。core 明确不碰 Wayland，
  panel 是只出二进制的 crate，所以消重的办法是再开一个共享 crate——为一个二十来行的探针加一层 crate
  边界不划算。两条路都只读 registry，不 bind 任何 global，重复的代价是"改协议名要改两处"，而协议名在
  core 的 `desktop::DATA_CONTROL` 常量里，只有一处。
- **`[app].export_format` 没有控件**：这个键是真的，但 v0 的 `plainly history export` 要求显式
  `--format`，从没读过它。给一个叫"命令行默认格式"的旋钮、而它什么也不做，比暂时不给这个旋钮更糟。
  键、`ExportFormat::ALL` 与窗口自己那条导出用的格式都已就位；等 CLI 那一侧开始读它，把控件加回来是
  一个 select 的事。
- **面板的行为键（位置 / 跟随显示器 / 自动消失 / 节开关）都写进了 `[app]`，但 v0 的面板一条都不读**（面板目前固定左上角、不会自动消失、节
  也全显示；消费者是面板的定位与退出路径票据）。设置页在四组控件下面明说了这一点，而不是让它们假装生效。`panel_display` 写的是
  `output-1` / `output-2` 这种**我们数得出来但叫不出名字**的占位：`wl_output` 只带厂商与型号，连接器名
  （`eDP-1`）来自 v0 不讲的 `xdg-output` 协议，所以这里不编一个名字。与面板对齐这个拼写是定位票据的事，
  `default_config.toml` 里写清了两种形态。
- **列表的本地日分组按 `Date` 的本地字段拼日期串**，不是拿 `getTimezoneOffset()` 做加减：那个值的符号
  与算术想要的相反，用它算出来的"天"会把日界落在当地下午，同一个下午的两条记录会被分到两组。
- **`app.ui_language` 也没有控件**，同 `export_format`：键是真的，但 v0 只有一份中文文案（`strings.rs`），
  一个改了什么都不变的"界面语言"下拉就是同一个空旋钮。文案已经集中，将来加语言时控件才回来。
- **显示器枚举到"第 N 块屏"为止**：`wl_output` 自己的事件只有厂商与型号，连接器名（`eDP-1`）来自
  `xdg-output`，那个协议 crate 在这台机器上取不到。所以设置里列出的是数量而不是名字，而不是列一个读
  不出来的名字。
