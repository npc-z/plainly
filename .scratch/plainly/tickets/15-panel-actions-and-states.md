## Comments

### 2026-10-06 来自票据 02 的挂点（在这里定，别以后当成漏做）

票据 02 交付的是 core 的渲染结构：`render::panel(passage, explanation, grammar_not_needed)` 返回 `Section { kind, body }`，节标题由面板自己按 `kind` 映射（`SectionKind::title()` 只是 markdown **文档**的标题，见其文档）——所以中文标题归本票据的 strings 模块。两件事留给这里：

1. **缺失的 Grammar**：core 保留该节、把文案交给调用方；本票据给出中文文案（规格 §12 已定「本段不需要」）并放进 strings 模块。
2. **无 Gloss 的 Key Help（一处需要明确表态的不对称）**：`Explanation` 的 `glosses` 可以为空（契约没有下界，ADR-0001），此时 core 在**两种表面都省掉** Key Help 节——因为规格只为 Grammar 定了文案，不给没定义的文案编一句。但「分不清『没有』与『没生成』」这条理由对 Key Help 一字不差地成立。**这里的决定**：面板是否为空的 Key Help 也说一句（如「本段无需解释」，文案进 strings 模块），还是认下这处不对称（更省，且不违约）。若选择说一句，core 的 `panel()` 要加第二个文案参数（一行）；**别绕开它**在面板里自己重建 section 列表——那样两处规则会分叉。
