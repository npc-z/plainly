# 主窗口的真机手测清单

规格 §13 排除的是**渲染**：面板与主窗口的绘制、图层、看门狗与退出路径没有自动化测试（自动化覆盖 core
的公共 API 与 CLI 二进制两条缝；窗口自己的决定由 `crates/plainly-desktop/tests/window.rs` 驱动）。
下面这些必须在真机上走一遍，因为它们要的是一块屏、一个合成器和一个真的剪贴板。

启动：`nix develop` 之后 `cargo run -p plainly-desktop`。

## 结构与导航

- [ ] `plainly-desktop --watch` 同样开窗，并在 stderr 说明监听没有实现、这个进程不会做任何事——
      它不该悄悄什么都不做，也不该假装自己在监听。
- [ ] 窗口是**普通窗口**，不是 layer surface：有标题栏、可拖动、可最小化。
- [ ] 顶栏两个标签（历史 / 设置）能切；切到设置再切回来，历史列表还停在原来的搜索结果上。
- [ ] 左列表约 330px，右详情占满剩余；窗口拉到最窄时列表不塌、详情不出横向滚动条。
- [ ] 列表按**本地日期**分组：今天 / 昨天 / 更早。跨零点以后（或把系统时区改到 UTC+13）一条「今天」的
      记录会挪到「昨天」——这是本地日分组的正确行为，不是 bug。

## 历史与搜索

- [ ] 搜索框下有一行「中文翻译暂不可搜」。
- [ ] 搜英文原文片段、改写里的词、某个 Gloss 的 expression 都能命中；搜译文里的中文**命中 0 条**。
- [ ] 点列表行里的标签 chip 变成筛选；再点「全部」清除。
- [ ] 同一段落用两个不同的提示词版本（改一下设置里的附录再解释同一段）会在列表里出现**两行**，
      两行的版本号不同——不被当成重复条目。
- [ ] 详情里加标签、点标签上的 × 移除；列表立刻反映。

## 详情与导出

- [ ] 详情五节顺序：原文 / 改写 / 关键帮助 / 语法 / 翻译；`grammar` 为 null 时显示「本段不需要」。
- [ ] 「复制 markdown」之后粘贴到编辑器里，是五节的 markdown，不是纯文本摘要。
- [ ] 「导出这一条」把文件写在数据目录里，界面念出路径；文件里**只有这一条**。
- [ ] 设置 → 数据 → 三条全局导出各写一个文件；文件名带时刻，三次导出不互相覆盖。

## 设置

- [ ] 语言与等级：四个等级各带一段含义，且含义随选择变化；把附录改一行，提示词版本（哈希）变化。
- [ ] Provider：列出五个预置 + 本机/云端标注；填 key 保存后顶栏说清楚存在哪（keyring / 环境变量 /
      仅本次会话）。`PLAINLY_DEEPSEEK_API_KEY=… plainly-desktop` 启动时，key 状态显示环境变量优先。
- [ ] 提示词：附录编辑器能写能存；「只能加不能删」的解释在；重启后附录还在。
- [ ] 行为：思考开关**默认关**；面板四个角 + 跟随当前显示器可选；自动消失开关默认关，关着时时长输入框
      **不可用**，打开后默认 20 秒；填 0 或 301 会被拒绝并说明范围。
- [ ] 行为：节标题下（它管全部四组控件）写着一次「这些已经写进 `[app]`，但 v0 的面板还固定在左上角、
      也不会自动消失、节也全显示」——因为它们确实还没被读；这一句只出现一次，不重复堆在每组下面。
- [ ] 被拒绝的改动（自动消失填 0、母语清空）：顶栏留下一条**中文**的「出错了：…」，控件回到文件里真正持有的值。
- [ ] 「复制自动弹」在 niri（有 data-control）下可点，并在开关下面写明「监听循环还没有实现：这个开关会写进
      配置，但 v0 不会真的在复制时弹面板」；在 GNOME 下**灰掉**并给出「需要 wlroots 类合成器的 data-control
      协议」这句话——是灰掉，不是隐藏。
- [ ] 面板位置/跟随显示器/自动消失三项落进 `~/.config/dev.plainly.app/config.toml` 的 `[app]` 段，
      且**没有**动到注释和其它键。

## 首次运行与降级

- [ ] 把配置与 keyring 都清空（`PLAINLY_DISABLE_KEYRING=1`、无 `PLAINLY_*_API_KEY`、临时 `XDG_CONFIG_HOME`），
      启动后**直接开在设置页**，并显示「还没有可用的 provider」那段空状态；没有独立引导流。
- [ ] 在该状态下填入 key（或把 provider 换成指向本机 runtime 后填入模型），窗口立刻能进历史页，
      不需要重启。
- [ ] 破坏 store（把 `history.db` 写成一个非 SQLite 文件）后启动：**窗口照样开**，每个屏幕都显示
      「打不开历史库或配置文件：…」这句人话，而不是白屏、也不是进程在 stderr 上留一行就退出。

## 单实例（⤢ 与重复启动）

- [ ] 面板里按 ⤢（或开两个终端跑两次 `plainly-desktop`）：**只有一个窗口**，第二次启动把已有窗口
      带到前面（show / unminimize / focus）而不是开第二个。
- [ ] 强杀窗口（`kill -9`）之后再启动：能起得来，不是报「另一个窗口开着」——`flock` 随进程消失，所以锁没有
      陈旧状态；留在磁盘上的 socket 文件由下一个持锁的启动删掉再绑定。
- [ ] `$XDG_RUNTIME_DIR/` 下有 `dev.plainly.app-desktop.lock` 与 `dev.plainly.app-desktop.sock` 两个文件；
      关闭窗口后两个**都留在磁盘上**（`flock` 随进程释放，文件不删），而下次启动照样能接管——锁没有陈旧
      状态，socket 文件由下一个持锁的启动删掉再绑定。
- [ ] 在 `$XDG_RUNTIME_DIR` 里放一个**同名普通文件**占住 `…-desktop.sock`：启动会把它删掉并正常开窗
      （此时是持锁的那一个，删除是安全的）。这是刻意选的取舍而不是 bug——锁已经判定只有一个窗口，socket
      文件只是交接用的通道。
